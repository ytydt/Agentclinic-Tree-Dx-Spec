# 阶段 2b：L2 组间判别 vs L1 先验增益

**数据**：`l2_vs_l1_metrics.tsv`，`l2_vs_l1_summary.json`。  
**口径**：各臂共享同一 mapper `option_maps`；将选项已匹配的 leaf_id 投影到该臂的叶序上，取 gold 选项最小叶秩 → option @1/@2/MRR（**公平重匹配**）。另报官方 mapper 在 L2-joint 上的真实分数。

## 1. 臂定义

| 臂 | 规则 |
|----|------|
| `L1-prior-only` | 按 L1 后验排序；每父取 1 个代表 L2 叶（joint 序中最先出现的子叶） |
| `L1-posterior+expand` | 全部 L2 叶按父 L1 后验排序（无组间重标） |
| `L2-joint` | A3 `final_ranking` 叶序 |
| `L2-joint-official-mapper` | 管线真实 mapper 输出（非叶序重匹配） |

## 2. 全量 100：公平重匹配

| 臂 | option @1 | option @2 | MRR |
|----|----------:|----------:|----:|
| L1-prior-only | **0.59** | **0.68** | 0.667 |
| L1-posterior+expand | 0.59 | 0.66 | 0.663 |
| L2-joint（重匹配） | 0.53 | 0.64 | 0.627 |
| L2-joint + 官方 mapper | **0.59** | **0.78** | **0.688** |

Δ（L2-joint 重匹配 − L1-prior-only）：**Δ@1=−0.06，Δ@2=−0.04，ΔMRR=−0.040**。

## 3. 子集 A（@2∧¬@1，n=19）

| 臂 | option @1 | option @2 | MRR |
|----|----------:|----------:|----:|
| L1-prior-only | **0.632** | 0.789 | 0.774 |
| L1-posterior+expand | 0.579 | 0.737 | 0.739 |
| L2-joint（重匹配） | 0.000 | 0.474 | 0.385 |
| 官方 mapper | 0.000 | 1.000 | 0.500 |

解读：在「当前系统已 @2 命中但未 @1」的病例上，**若改用 L1 代表叶序重匹配，约 12/19 可虚拟拿到 @1**。说明 joint 组间排序在这些近失败例上**伤害首位校准**；官方 mapper 的高 @2 来自关系感知评分，不能掩盖叶序本身把 gold 相关叶放在 #2+ 的问题。

## 4. 解释对照计划中的分支

| 假设 | 数据支持？ |
|------|------------|
| L2 相对 L1：**@2 大涨、@1 不涨** → 组间扩覆盖、组内/仲裁未校准 | **部分。** 官方 mapper @2(0.78) ≫ L1 重匹配 @2(0.68)，但公平叶序重匹配下 L2 并未抬高 @2；高 @2 大量来自 **mapper 协议**，而非单纯 joint 叶序。 |
| L2 相对 L1：**@1/@2 皆无增益** → 怀疑树/生成 | 叶序重匹配下 L2 **略负**；不宜只加 MAC 式开放重排。 |
| L1 代表叶 @1 已接近 MAC → joint 引入噪声，应可 **fallback L1** | **强支持**（A 集虚拟 @1≈0.63 ≈ MAC 全量 @1）。 |

## 5. 设计含义

1. 融合打分应作用在 **L2 Top-K 封闭池**，并允许 **L1-prior 序作为 fallback / 软先验**。
2. 不得声称「仅引入 L2 组间」已带来稳健 @1 增益；现阶段 L2 的主要可辩护收益是 **官方管线 @2/MRR**，需护栏保住。
3. `L2-local-only` 臂日志未完整拆出（local champion 边际未单独落盘），本阶段标为 **未测 / 后续可选**。
