# 金标盲冻结 Top2：为何不作弊，以及实测结果

## 1. 为什么「金标盲冻结 Top2」不作弊

作弊 / 神谕，在本语境中指：**决策规则在推理时用了评测才知道的正确答案**。

| 护栏 | 决策依据 | 推理时是否可得 | 判定 |
|------|----------|----------------|------|
| 金标感知 G2（烟测 0.69） | 「金标已映射叶是否仍在 Top-2」 | 否（金标不可见） | **神谕 / 有作弊嫌疑** |
| **金标盲冻结 Top2** | 「校准后 Top-2 **集合**是否仍等于校准前 Top-2 **集合**」 | **是**（只依赖系统自己刚产出的 joint Top-2） | **不作弊** |
| harness 无 G2（正式 0.65） | 不做该集合约束 | 是 | 不作弊 |

金标盲规则的输入只有：

1. 校准前封闭池顺序（joint 已给出）；
2. 校准后提议顺序（support / pair / L1 fallback 算出）。

二者都不含 gold 选项字母、不含「哪一叶命中了答案」。它只是一条**对系统自有中间状态的集合单调约束**：允许 Top-1/Top-2 **对调**，禁止把第 3 名及以后的叶换进 Top-2 而挤出原 Top-2 成员。这与「用答案决定是否回退」不是同一类操作。

（研究自由度另说：是否采用该约束可以事后选型；那是方法选择问题，不是金标泄漏。）

## 2. 算法（软冻结）

若 `set(post[:2]) != set(pre[:2])`：

- 取出 `pre` 的两个成员，按其在 `post` 中的相对次序排到最前；
- 其余叶按 `post` 中剩余次序接在后面。

实现：`topk_calibration.top2_set_guard(..., preserve_full_top2_when_no_gold=True)`。

## 3. 100 例实测（`both_l1fallback`，同一 LLM 缓存）

| 口径 | option @1 | option @2 | MRR | 修复/回退次数 |
|------|----------:|----------:|----:|-------------:|
| ours | 0.59 | 0.78 | 0.688 | 0 |
| harness（无 G2） | **0.65** | **0.79** | **0.720** | 0 |
| **金标盲冻结 Top2** | **0.59** | **0.79** | **0.690** | **79** |
| 金标感知 G2（神谕） | 0.69 | 0.79 | 0.740 | 44 |

相对 harness：盲冻结在 79 例上改写了 Top-2 集合相关排序；@2 不降，但 **@1 增益被抹平**（回到 0.59）。修复子集上相对 harness：@1 损失 11 例、增益 5 例；@2 无额外回退损失。

## 4. 解释

`both_l1fallback` 的 @1 提升，相当一部分来自 **改变 Top-2 成员集合**（例如把更贴金标的叶从第 3 名抬进 Top-2，或 L1 回退打乱原 Top-2）。金标盲冻结恰好禁止这类集合变动，只留下「原 Top-2 内部换序」——对 @1 帮助很小，故点估计回到 ours。

## 5. 结论

- **不作弊**：决策不依赖金标。
- **作默认护栏不划算**：在本数据上保住 @2，但吃掉 harness 的 @1 +0.06。
- **正式数字仍建议**：harness 无 G2 → @1 **0.65** / @2 **0.79** / MRR **0.72**。
