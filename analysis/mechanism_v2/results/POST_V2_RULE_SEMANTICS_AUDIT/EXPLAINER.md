# 这个目录在讲什么（面向初次阅读者）

共用术语见 [../READER_GUIDE.md](../READER_GUIDE.md)。本文只讲这个目录独有的东西。

## 一句话

有人怀疑「指南原文 → 结构化规则」这一步的语义扭曲还很严重。这个目录去查了，**结论是确实严重，而且比之前以为的层数更多**：错误不只出在大模型身上，schema、后处理程序、匹配器和执行器各自也在制造新错误。

## 它做了哪几件事

1. 从原始缓存把四个实验臂的 **140,652 条断言**重建了一遍，逐字段比对，确认存档没被改动过。
2. 挑了例 74（一个心律失常病例）做**完整证据链追踪**——从指南原文一路查到最终排名。
3. 逐段读了之前用来评估「逻辑保真度」的全部 41 个文本片段，检查那把尺子本身是否在量对东西。
4. 构造了 **27 个合成反例**，每个隔离一处引擎语义缺陷。
5. 回到原始 XML，确认语料入库修复之后还剩哪些结构损坏。

## 需要解释的专用说法

| 说法 | 平实解释 |
|---|---|
| **定点消融（targeted ablation）** | 只删掉一条特定的错误规则再重跑，看结果怎么变。对照的是「全局消融」——把某一整类规则全删掉。两者结论可以完全不同。 |
| **首次损坏位置** | 一条规则从原文到最终排名要过好几道工序。审计要标出它**最早**在哪一道被弄坏的，而不是笼统说「抽取错了」。 |
| **合成见证 / counterexample** | 人为构造的一个最小输入，喂给真实生产代码，证明「这段代码在这种情况下会给出错误答案」。它证明缺陷存在，**不告诉你这种情况在真实病例里出现多少次**。 |
| **S/I/A/G/Q/R/C/P/J/E/W/M 十二类错误码** | 审计提出的错误分类框架：来源、身份、原子、组拓扑、量词、方向效力、适用范围、程序改写、病例接合、执行动作、证据计数、测量。一条规则可以同时中好几类，不是单选。 |
| **observed_hard_harm / observed_soft_effect / latent_semantic_defect / ambiguous_source** | 给每条错误再标一个「后果等级」：真的造成了淘汰、只影响了分数、目前潜伏没触发、还是原文本身就有歧义。**「没触发」不等于「没错」。** |
| **参照语义（reference semantics）** | 审计自己写的一个**小型正确实现**（40 项检查），用来演示「如果按原文语义正确执行应该是什么样」。它只是审计的标尺，**没有接进生产流水线**。 |
| **default_stale / exact_arm_window** | 两种取原文窗口的方式。前者是历史代码的默认行为（会去找旧检索来源，是个已证实的缺陷），后者是各臂真实的窗口。审计两种都跑了，发现**11 例的排名全部不变**——所以这个缺陷是真的，但不是排名回退的原因。 |
| **空重复候选** | 候选列表里同一个病出现两次（只差大小写），证据全落到第一个身上，第二个是 0 分空壳却仍占一个名次。例 74 报告出来的「金标第 4 名」就来自这个空壳，真正拿到证据的那个在第 10 名且已被淘汰。 |

## ⚠ 编号撞车警告

这个目录的引擎反例编号 **E01–E26**，和主报告的门闸规则编号 **E1–E17 是两套完全不同的东西**。

最容易搞混的一对：

- 本目录 **E17** ＝「基数计的是输出行数，不是不同的判据」
- 主报告 **E17** ＝「没有排除线索的 `excludes` 要降级」

而主报告的 E17 实际对应的是本目录的 **E23**。

## 读结论时的边界

- 所谓「逐段人工式复核」是 **AI 审计员**读原文写反例，不是人类临床专家双盲审阅。
- 例 74 和其他样例是**按问题富集挑的**，不能用来估算总体错误率。
- 27 个反例用的是隔离配置，**不等同于**临床交付配置 B1+S7。
- 本轮**不能**据 11 例声称 v2 导致总体临床准确率下降。

## 最重要的三条结论

1. **§35 的三条结论要撤回或收窄**：「抽取已达可用程度」「不是判据组的锅」「高权关系产量增加即改善」。
2. **例 74 的因果解释被推翻**：之前说「删掉 excludes 后只回到第 2，说明还有别的损失」。实际上全局删除**额外复活了竞争者 LQTS**；只删那一条错误规则，两个 v2 臂的 CPVT 都直接回到**第 1**。
3. **历史性能指标本身受污染**：错误的金标映射、重复候选、以及干预范围混淆。
