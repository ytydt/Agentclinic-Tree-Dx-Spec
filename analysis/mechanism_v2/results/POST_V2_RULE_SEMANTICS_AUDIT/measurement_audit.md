# §34–35 抽取质量测量的独立复审

本复审只使用本地已存在的四臂抽取、检索、报告和脚本，无新增模型调用。审读对象是来源文本与抽取结构之间的逻辑对应关系，不是对患者作临床诊断。下述“逐条审读”由一个独立 AI 审计代理完成，未经过两名临床专家双盲裁决。

**结论：§34 确实测到了“所报告组的引文更常跨原文行”，但没有建立“组合规则的语义正确性提高”。§35.4 的高权关系增产不能证明必要/充分关系的降级错误已被修复；§35.5 据此宣布“语料与提示词已解决到可用程度、瓶颈换到层一”，证据不足。** 源端修复、语义抽取、组表示、实例接合与执行仍可同时有缺陷。确定性重算能重复错误的测量，不会使被测构念自动成立。

## 2. “logic 保真”的参考答案首先就不可靠

`stated_logic()` 在整个窗口上按 `ALL_OF`、`ANY_OF`、`N_OF_M` 的顺序搜索；遇到一个匹配就给整段分配一个 `all / any / at_least_n` 标签。它没有先确认数字是判据数、`all` 的辖域是患者发现、引导句在谈诊断，或窗口内是否有多个不同规则。

对 v2 的全部 41 个入选位置逐项审读得到：

| 所选正则触发片段的性质 | 数量 | 能否直接充当单个诊断组合的逻辑金标 |
|---|---:|---|
| 诊断或诊断修饰项判据 | 8 | 仍须保留嵌套、时间、对象与效力，不能只给一个标签 |
| 临床怀疑或转诊行动规则 | 6 | 不能把怀疑/转诊效力改成确诊；含重叠窗口 |
| 分级风险评分 | 1 | 需要“计数→风险”映射，不能替成一个阈值标签 |
| **正则触发片段并非诊断组合判据** | **26** | **不能用该触发位置给整段规定诊断连接词** |
| 合计 | 41 | — |

这里的 **26/41 指正则选中的触发片段，而非 26 个完整段落完全没有任何诊断信息**。例如 gid338188 本身讨论 Alzheimer 诊断，但触发 `all` 的句子是在说这些症状的起病年龄；不能把那个 `all` 用作段内所有诊断断言的金标。这个结果是测量工具的构念有效性问题，不是来源覆盖率下降。

几个可以直接核对的错误触发：

| gid | 匹配到的内容 | 当前标签 | 实际对象 |
|---|---|---|---|
| 628186 | `2.5% to 5% of these cases` | `at_least_n` | 患病构成比例，数字 5 不是判据数 |
| 403899 | `[2] Of these forms` | `at_least_n` | 引用标号 2 |
| 869628 | 图号 `11.2` 后接 `majority of these` | `at_least_n` | 图号与比例描述 |
| 444828 / 444829 | `all deliveries, with about 25% of these cases` | `all` | 人群发生比例，且两个窗口重复 |
| 851295 | `All of these drugs ... penetrate the blood–brain barrier` | `all` | 药物性质 |
| 522304 | `management includes all of the above specialists` | `all` | 团队组成 |
| 716474 | `All three of these regions fuse at 16 to 19 years` | `all` | 发育解剖 |
| 212407 | `calculate all of the above indicators` | `all` | 指标计算工具 |
| 382014 | `abuse should be considered in each of the following` | `all` | **任一场景足以触发考虑**，连接词应为 any，效力也只是考虑 |
| 652917 | Brugada / Vereckei VT 诊断算法 | `all` | 原文明说单个 Brugada 判据即可；aVR 子组也明说 any |

最后一例尤其说明“按整段关键字打标签”会误伤正确抽取：`N_OF_M` 从 `both ... lead V1-2 and V6 If any single one of the above` 这类跨子句串联中取到 `both`，判为 `all`，却没有正确读取该段真正的诊断效力句。整个窗口至少涉及一个 OR 主组、一个 OR 子组及成员内部的 AND/量化结构，根本没有一个可代表全段的单一连接词。

## 3. 引文连接把大量断言配给了错误的测量对象

三个 fidelity/TVD 脚本把各病例的断言平铺后，遍历所有“判据段落”，只要正规化后的引文是某段的子串，就归给第一个匹配段落并停止。连接过程中不要求病例相同、不要求 `_source / _title / _section` 相同，也不使用原始 passage/task 标识。

| 臂 | 已连接断言 | 目标段落 source/title 与断言元数据不同 | 目标 gid 没有被该病例检索 | 引文可匹配多个判据段落 |
|---|---:|---:|---:|---:|
| 旧提示 / 旧索引 | 1,096 | 502 | 197 | 367 |
| 新提示 / 旧索引 | 1,026 | 452 | 196 | 352 |
| 旧提示 / v2 | 1,363 | 684 | 225 | 455 |
| 新提示 / v2 | 1,240 | **597** | **218** | **402** |

各列可以重叠。这些数不是临床错误率，也不表示每条同文异源引文都含错误知识；它们表明该连接不能证明“这个模型输出就是从被评价的那个来源判据抽出来的”。新提示/v2 中，48.1% 的被连接行连基本 source/title 都不一致，17.6% 被挂到该病例未检索的 gid。

具体后果包括：

- 一段中的普通症状短语可以吸走其他疾病、来源与病例的断言，影响整段的多数 logic。
- 两个重叠窗口中的相同判据会被先到者吸走；gid27456 有本来源的抽取行，但代理脚本可把引文全部归给先出现的 gid27457，使 27456 被当作 `NOT_REACHED`。
- 后续把段落去重，并没有撤销“别的病例/其他 focus 输出的多行投票改变这个段落标签”的依赖。

因此，引用子串命中只能作为寻找候选来源的线索。测量抽取保真必须使用原始请求身份绑定，再在同一来源规则中比对成员与效力。

## 4. TVD 与配对翻转没有检验规则语义是否正确

`calc_logic_distortion.py` 对每段统计所有已连接断言的 logic。只要出现任何合法分组标签，就在合法标签之间取众数；`NO_GROUP` 即使占绝大多数也被忽略。新提示/v2 有 **25 个段落**属于“存在分组，但 NO_GROUP 行数多于所有分组行数之和”。所以所谓“成组率”不是完整规则的召回率。

“logic 保真”也没有检查：

- `at_least_n` 的 `n` 是否正确，例如 2 和 3 无区别；
- 应有成员是否完整、是否重复计数；
- 两层子组、必须包含的子集、AND/OR 辖域；
- 必要/充分/排除方向、否定作用点、效力与适用对象；
- 症状是否带条件、持续时间或替代解释；
- 原文讲的是疾病、诊断操作、筛查、转诊还是文献选择。

TVD 比较的是三类标签的**边际分布**。来源端分母是所有被正则挑中的段落，输出端分母却是至少产生一个合法分组标签的段落。两个条件分布不同；未到达/未成组在输出分布中消失。

即使参考标签完全正确，TVD 也不是实例保真率。三个来源规则分别为 `all, any, at_least_n`，预测依次为 `any, at_least_n, all`：三条全错，但分布完全相同，**TVD=0**。不能把 TVD 下降解释成组合语义净修复。

对报告所称 v2“5 修 1 坏”定位后，内容如下：

| gid | 代理翻转 | 原文审读 |
|---|---|---|
| 889603 | `all → any`，计为修好 | 紧张症可见于五类精神障碍的关联列表，不是患者诊断判据组 |
| 889487 | `any → at_least_n`，计为修好 | 恢复部分数量结构，但疾病被错绑且必须含前 3 项之一的子约束未表示 |
| 889594 | `any → at_least_n`，计为修好 | 恢复 3 的标签，但组成员有局部限定丢失及重复来源问题 |
| 794222 | `NO_GROUP → at_least_n`，计为修好 | 窗口仍在躁狂症状清单中途结束，数量标签不证明成员完整 |
| 212407 | `NO_GROUP → all`，计为修好 | “计算全部指标”的工具说明，被当作诊断组合改善 |
| 892708 | `all → NO_GROUP`，计为改坏 | “各障碍之间统一判据”的元说明；放弃伪分组可能是合理行为 |

这里不是用临床主观意见替换统计结果：两项“修好”和唯一“改坏”所比较的本来就不是对应的诊断组合。原来的符号检验 p 值只能描述这个错误代理终点上的标签变化。

## 5. 跨行成组计数可复现，但身份、分母和独立性不足

四臂跨行组数 **37/540、40/390、119/612、158/500** 均按原脚本复现。可以保留的描述是：在被脚本归成多成员组的输出中，新提示/v2 的来源行跨度更大。

然而：

1. **指标衡量版面跨度，不衡量逻辑闭合。** 原文恢复换行本身就使“跨行”的机会变多；将同一个已经错误的 OR/AND 组跨多行复制也会提高指标。
2. **分母受处理影响。** 旧索引更改提示后，跨行组绝对数只从 37 增到 40，而分母从 540 降到 390。比例从 6.9% 到 10.3% 不等于召回了相应比例的新正确判据。
3. **缺少真正的局部组身份。** 分组 key 是 case、source、title、section、focus、局部 group_id；没有 passage/task ID，且未纳入 subject。不同调用都可以合法使用 `g1`。这能合并多个窗口或不同主体的组。
4. **允许部分定位即宣称跨度。** `locate()` 找包含最多引文的段落，不要求包含全部成员；`span_of()` 只利用找到的引文。找不到某些成员不会阻止一个组被计为跨行。
5. **第一成员代言所有成员。** logic 分布取 `v[0].criterion_group.logic`，同一组内不同 logic/n 不会成为错误项。

| 臂 | 多成员组 | 混合 logic | 混合 n | 混合 subject | 仅部分引文可定位 | 其中仍计为跨行 |
|---|---:|---:|---:|---:|---:|---:|
| 旧提示 / 旧索引 | 540 | 20 | 8 | 20 | 99 | 6 |
| 新提示 / 旧索引 | 390 | 20 | 4 | 18 | 64 | 5 |
| 旧提示 / v2 | 612 | 18 | 6 | 24 | 120 | 16 |
| 新提示 / v2 | 500 | **19** | **6** | **25** | **84** | **22** |

这些类别有重叠，也不应一律归因给模型：混合值可能由后处理跨调用组 ID 碰撞造成。原始请求级审计才能区分模型输出内部不一致与拼接器制造的不一致。

用包含谓词、关系、情态、上下文、阈值、引文等字段的保守指纹，忽略 case/focus/局部 group_id 后，新提示/v2 的 500 个组只有 469 种组内容，含 31 个额外重复实例；组内另有 23 个相同字段与引文的重复成员。这还没有把同义 focus、措辞轻微不同及邻接重叠归为同一来源规则，因而只是可直接发现的重复下界。

§34 将“组为单位，各臂独立”的比例 z 检验作为显著性依据不成立：四臂面向同一病例和相近来源任务，病例内、来源内、重叠窗口内、同一来源不同 focus 的输出相关，同一个规则还可能反复出现。报告给出的标准误和 p 值没有体现这些依赖。当前数值可以作为探索性描述，不能据之宣布抽取能力改善显著、主终点已有功效。

进一步地，按出现的组作为分析分母，缺失组在某个臂中根本没有配对单位。应先冻结独立来源规则清单，把所有输入规则都放进分母，缺失、错误合并、错误拆分分别记错；统计上按来源规则配对，并考虑文档/病例簇，而不是将每个输出组当成独立新样本。

## 6. 高权关系的“产量”不是正确性

`required_for` 从 839 到 1,162，`sufficient_for` 从 108 到 158，是标签计数。没有对新增/消失行逐源配对裁决，无法知道增加的是真正恢复的刚性判据，还是原本软证据、流程要求、预后关系被错误升格。提示还捆绑了文献过滤与新分组措辞；“新提示只改成组范围”与 §34.5 自己承认的捆绑并不一致。

在同一个新提示/v2 结果中，已找到下列明确反例（详见 JSON 精确行索引）：

| ID | 原文语义 | 实际抽取错误 |
|---|---|---|
| E01 | 认知缺陷不**仅仅**发生于谵妄期间 | `absence of delirium`，必要且强制 |
| E02 | 其他精神障碍不能**更好解释**认知缺陷 | `absence of other mental disorder`，必要且强制 |
| E03 | Brugada 算法的任一项用于诊断 VT | 赋给 **Brugada syndrome**，成员 `required_for` |
| E04 | Vereckei aVR 明示 any one | 抽为 `all`，主体甚至成为 `Vereckei Criteria` |
| E05 | DSM F20.9 schizophrenia 新判据块 | 继承前段主体，写成 schizophreniform disorder |
| E06 | 2/5 且前 3 项至少 1 项 | 扁平 `at_least_n=2` 无法表示重叠子集 |
| E07 | 不受外界刺激影响的 agitation 才计入 | 可执行谓词仅有 `Agitation` |
| E08 | Mutism 成员排除已知 aphasia | 成员局部排除条件只在引文，结构中缺失 |
| E09 | 腹痛 AND 附加条件才怀疑 diverticulitis | 腹痛与其余成员共同放进一个 `any` |
| E10 | DLB 的 2/3 集合整体必要 | 每个叶子也写 `required_for`，必要性辖域冲突 |
| E11 | Kocher 成员数映射不同风险 | `any` 列表失去计数→风险映射；参考 `at_least_n` 也不正确 |
| E12 | CPVT 未早诊时预后较差 | `early diagnosis required_for CPVT` |
| E13 | 缺血卒中溶栓前可能需要凝血检查 | `coagulation studies required_for ischemic stroke` |
| E14 | 可能需要做 EEG 评估癫痫障碍 | 变成必须具有**异常** EEG |
| E15 | type I ECG pattern 是必要条件 | 抽为 `pathognomonic_for`，必要→充分反向 |
| E16 | ECG type 1 是唯一**可能**具诊断意义的型态 | `obligatory pathognomonic_for`，模态升格 |
| E17 | 不得用 EEG 排除 epilepsy | 用 `excludes + negated` 表示禁止推断，缺少元规则类型 |
| E18 | 诊断不确定时可考虑 EMB | `EMB required_for ARVC` |
| E19 | 定义中要求没有高血压等解释 | `absence of hypertension` 反成 asserted `excludes` |

并非每个反例都已经证明在这 11 例触发下游误杀。E07–E08 是可执行字段丢失限定，E10 是必要性落在叶子还是组上的危险歧义，E17 是“禁止某个推断”缺少正确元规则表示。把它们区别于已确定的实体错误、连接词错误与方向错误，可避免用静态风险冒充真实运行因果证据。各例都给出一个能区分来源规则与抽取规则的反例赋值，便于下一轮做确定性语义检查。

尤其需要纠正一个优化目标：**`any` 多并不天然坏，`all` 或 `at_least_n` 多并不天然好。** 若来源规则是 `(A∨B)→D`，正确的 OR 组本身就可以具有充分诊断效力；若是 `(A∨B)→¬D`，任一成员可以是刚性排除项。当前引擎的“any 永远不刚性”是表示/执行限制，不能倒过来把压低 any 比例当作源文本保真的目标。

## 7. 对 §34–35 应如何改写

| 原叙述 | 证据允许的改写 |
|---|---|
| 跨行率显著改善，说明语料/提示两个杠杆有效 | 原脚本的跨行代理指标上升；输出组依赖、分母改变与组身份问题使原 p 值不可用于语义能力结论 |
| logic 分布朝正确方向移动，保真提高 | 正则标签一致性与边际分布变了；参考标签和引文连接存在实质错误，须撤回其语义保真解释 |
| 高权关系恢复，降级问题得到部分修复 | 高权标签产量上升，新增标签的精确率与完整组正确率尚未测定 |
| 语料与提示词已解决到可用程度 | v2 恢复了部分可见内容；本轮原文/抽取反例证明关系方向、效力、辖域、对象与嵌套仍未达可依赖状态 |
| 瓶颈从组抽取迁移到层一太刚 | 层一可造成伤害，但抽取与表示缺陷仍并存；阶段消融只识别特定运行路径，不能宣告其余环节已经正确 |
| F4b 对 top-1 无变化，因此不是组的锅 | 该消融只覆盖指定的 all 组否决开关；不能排除组误拆、错误成员作用于单条规则、组软分数、来源聚合与候选错误绑定 |

最后一项还需结合主审计的实际执行路径、版本与缓存接入核验。这里不重新声称它对金标位次的效应量。

## 8. 可以真正测量的下一轮终点

建议先冻结一批与输出无关的来源规则，包含原文已完整可见、来源自身残缺两类，并以**原始来源规则**为单位保存：文档身份/版本、精确跨度、目标疾病或行动、适用上下文、原子成员及局部限定、AND/OR/NOT/数量/时间结构、整体效力与方向、成员完整性和重复关系。

每个来源规则至少测五种不同终点：

1. **结构召回**：是否有输出覆盖该规则；缺失不能从分母剔除。
2. **整体语义精确率/召回率**：实体、方向、组边界、成员、数字、辖域、效力全部通过才算严格正确。
3. **错误效力升级率**：支持/怀疑/流程/预后等是否被提升为必需、充分或排除；单独统计会误杀的方向。
4. **可区分赋值验证**：为每条规则构造来源与抽取不同结论的边界例，如 2/5 但不含前 3、存在其他精神障碍但不能更好解释、OR 恰满足一项。对于语义尚不能确定的来源，标记待审而不强行生成硬规则。
5. **路径隔离后的下游效应**：只有在来源与抽取语义经过核验后，固定候选与患者发现，比较正确规则、原始规则、禁用错误规则的配对回放；把表示错误、匹配错误、执行错误与分数累积区分开。

推断方向必须成为类型契约，而不只是在一个含糊的 `relation` 字符串与 `polarity` 中自由组合。例如应明确区分“满足条件→排除”“不满足必要条件→排除”“禁止用此测试排除”“当前证据不足以确认必要条件”。这几者在开放世界病例文本下有完全不同的执行结果。

允许输出“不确定/原文不完整/不能在当前类型中忠实表达”，并将其计为覆盖损失；不要把缺少 `n` 的 `at_least_n` 自动改成 `any`。`normalise_group()` 当前确实存在此回退路径：它只是造出合法枚举值，未得到来源授权的阈值放宽仍是语义改写。这是可读代码确认的风险路径，本复审未将它计为已发生的 19 个案例之一。

在上述终点建立前，值得保留 v2 对内容可见性的修复，同时停止用更多跨行、更少 any、更多 required/sufficient 作为正确抽取的替代目标。
