# 补齐来源后的规则语义：人工审计参照契约

本文件与 `reference_semantics.py` 是**审计原型**：给人工复核、故障复现和最小修复提供一个可执行的语义参照。它们不抽取指南，不解析病例，不参与候选排序，不修改现行生产引擎，也不证明任何临床规则正确。实际病例与源码证据见同目录主报告和 case74 审计。以下 P、Q、R、D、A 均为合成命题；所有数字示例也均为合成，不是医疗标准。

必须分开的四件事是：**来源到底说了什么；结构化规则是否忠实；病例是否满足该规则；满足或不满足允许推出什么。** 单独增加来源覆盖，只能修复第一层的部分缺失。

## 1. 先固定蕴涵，再计算命题真假

令 D 表示“目标疾病成立”，G 表示完整判据组，A 表示已核实的适用范围。以下关系均限定在 A 内，不能跨人群、检查情境或定义版本使用。

| 来源获准表达的关系 | 形式 | G 为真时 | G 为假时 |
|---|---|---|---|
| 必要条件 | D ⇒ G | 不能仅据此确诊 | 可推出 ¬D，但须确认这是疾病成立所必需的完整条件 |
| 充分条件 | G ⇒ D | 可推出 D | 不能仅据此排除 |
| 满足即排除 | G ⇒ ¬D | 可推出 ¬D | 不能仅据此确诊或排除 |
| 支持、常见、相关 | 不承诺上述硬蕴涵 | 仅支持或描述 | 不产生硬结论 |

这里“必要条件不满足即可排除”是经典蕴涵的逆否命题；实际使用的难点在于：**指南是否真的承诺 D ⇒ G，而非仅给出一种确诊路径、分类标准或常见表现。** “未达到此诊断标准”“本检查不支持”“该路径未确诊”不自动等于疾病不存在。将关系标签写成 `necessary`，也不等于已经完成这种来源核验。

三个最小反模型：

- G ⇒ D 为真时，G 假而 D 真完全可能。因此，充分路径失败不能推出 ¬D。
- D ⇒ G 为真时，G 真而 D 假完全可能。因此，必要条件满足不能推出 D。
- G ⇒ ¬D 为真时，G 假而 D 真完全可能。因此，满足即排除不能改写成不满足即排除。

`reference_semantics_results.json` 保存以上反模型的机器检查及三类蕴涵在四种输入状态下的全部 12 行结果。规则中出现“no / absent / without / 阴性”只改变**命题的正负号**，不决定其是哪种蕴涵。

## 2. 最小可审查表示

以下是结构示例，`source` 中占位值必须由真实来源定位替换。一个规则对象保存完整组及其适用范围；叶节点另有证据定位，不能把所有叶都指向一个模糊的章节名。

```json
{
  "rule_id": "sha256:<canonical-immutable-rule>",
  "source": {
    "document_sha256": "<exact-source-content-sha256>",
    "edition": "<version>",
    "source_anchor_id": "<document-and-span-identity>",
    "span": {"page": 1, "table": "synthetic-table", "rows": [1, 2, 3]},
    "required_context": ["caption", "column-headers", "footnotes"],
    "source_type": "synthetic-example-not-clinical"
  },
  "target_concept_id": "D",
  "target_granularity": "exact-defined-concept",
  "relation": "necessary",
  "scope": {"op": "literal", "fact": "A", "polarity": true},
  "criteria": {
    "op": "all",
    "members": [
      {"op": "literal", "fact": "P", "polarity": true},
      {
        "op": "any",
        "members": [
          {"op": "literal", "fact": "Q", "polarity": true},
          {"op": "literal", "fact": "R", "polarity": false}
        ]
      }
    ]
  },
  "certifications": {"certified_D_implies_G": true},
  "leaf_source_spans": {
    "P": "<P text span>",
    "Q": "<Q text span>",
    "R": "<R text span; polarity belongs to the expression>"
  }
}
```

它表达的是 `A 内：D ⇒ [P ∧ (Q ∨ ¬R)]`，而不是三个可独立排除 D 的规则，也不是 `P+Q−R`。`polarity:false` 表示 ¬R；`relation:necessary` 表示 D 指向完整组。两字段相互独立。

用于去重的身份至少分两层：来源锚点标识“同一段原文”，规则内容哈希标识“该段的这一个解释版本”。修改连词、极性、阈值、范围或蕴涵必须生成新规则身份，并保留 supersedes 关系；不得静默覆盖旧结果。相同原文经多个 chunks、查询或来源转载得到的重复条目不能成为独立证据。内容哈希只能识别完全相同的规范化表示，**不能自动证明同义规则等价**。

`reference_semantics.py` 中的 `rule_id` 演示规范化内容哈希；它没有实现来源数据库、版本迁移或等价去重。`certifications` 是人工完成来源核验后的声明，不是 LLM 自报置信度；示例脚本不具备验证声明真实性的能力。

## 3. 连词、量词、评分和作用域不能互换

**逻辑组。** `all`、`any`、`at_least(n)` 必须保留嵌套。`P ∧ (Q ∨ R)` 与 `(P ∧ Q) ∨ R` 不同；后者会在 P 假而 R 真时错误通过。全局复用 P 的事实身份不等于删除 P 在不同子组中的引用，例如 `(P∨Q)∧(P∨R)` 的两个引用都必须保留。

**计数。** `at_least(2,[P,Q,R])` 的计数单位是来源规定的不同判据，不能是三个检索命中、三个同义表述或一个判据的三个重叠摘录。已知真数为 t，未知数为 u，则：

- t ≥ n：已足够满足；
- t + u < n：即使未知全真也不足；
- 其他情况：尚不能判定。

这些是忽略成员依赖时的安全边界。若成员共享变量或相互排斥，必须保持依赖。例：`at_least(2,[P,¬P])` 中，P 未知时逐成员边界为 [0,2]，但同一个 P 在任何可能世界中只能使一项为真，真实可行边界是 [1,1]，因此此组恒假。原型通过枚举一致的有限布尔赋值保存这种依赖，而不是为每次出现的 P 独立掷一次硬币。

**量词域。** “任何一次”“至少两次”“所有一级亲属”“同一时间窗内”还需要可识别的对象集合、去重键、时间窗、观测完整性和取值单位。列出三个已知对象不等于量词域只有三个对象。域不完整时，未发现存在性见证不能证明不存在，已检查对象全部满足也不能证明普遍量词成立。原型仅执行显式有限成员组；开放域、事件频次和时间约束须由审计员先建立正确的域，未实现自动量词解析。

**评分系统。** 带正负分的表格应保持为独立类型，例如下面的合成表示，而不能假装成逻辑计数：

```json
{
  "kind": "score_criterion",
  "source_anchor_id": "synthetic-score-example",
  "terms": [
    {"criterion_id": "P", "points": 3},
    {"criterion_id": "Q", "points": 3},
    {"criterion_id": "R", "points": -1}
  ],
  "aggregation": "sum_subject_to_source_selection_rules",
  "threshold": {"comparator": ">=", "value": 4},
  "meaning_if_met": "source-defined-category",
  "meaning_if_not_met": "category-not-established-by-this-score"
}
```

P、Q、R 都满足时得 5 分，仍超过示例阈值 4。可见 **R 贡献 −1 分并不蕴涵 R ⇒ ¬D**。负号属于评分，不是硬排除的方向。分档互斥、同一类别只取一档、扣分上限、缺项处理等必须从表头和脚注逐项恢复。通过评分阈值也不自动取得硬确诊意义；仍由来源对该阈值的定义决定。参考程序明确拒绝 `op:score`，没有暗中给出一个未验证的临床评分实现。

**适用范围。** 若来源有不同年龄、家族史或检查条件下的替代路径，应分别保存 `(A₁,G₁)`、`(A₂,G₂)`，以及每条路径的蕴涵。不能把 A₁、A₂、G₁、G₂ 平铺成一个总分或同一个 AND。A 未知或冲突时不能强行执行该路径。某个必要性要求若只适用于 A₁，不能用 A₁ 不成立去排除 A₂ 中的疾病。

## 4. 未知、冲突和“未满足”是三种不同情况

观察层保留四种状态：`true`、`false`、`unknown`、`inconsistent`。病例未写某项，默认为 unknown；只有适用时点与检验条件下的明确证据才可标 false。阳性和阴性记录冲突时保留双方证据，不能把冲突折成 false。

原型对 unknown 使用共享变量的有限可能世界语义：所有一致赋值中组都真则 true，都假则 false，否则 unknown。故 `P∨¬P` 在 P 未知时恒真，而 `P∧¬P` 恒假。这是审计用的布尔语义，**不表示真实医学谓词在任何采样时点都适用经典二分**；不适用和测量不确定性应在事实定义及范围层保留。

只要引用了 inconsistent 事实，原型就把整个表达式隔离为 inconsistent，停止硬推断。这是保守审计约定，未实现完整的四值逻辑推理。若不同规则分别导出 D 和 ¬D，应记录冲突并回溯来源、目标概念及适用范围；不能让任一侧靠重复条目数量获胜。本原型没有跨规则冲突裁决器，也没有临床排序器。

`criteria=false` 只表示这个完整命题组不满足。只有在 A 已核实为真且来源核准 **D ⇒ G** 时，才允许据其推出 ¬D。未满足充分路径、评分分类、研究纳入标准或常见表型组，不具备这一权限。

## 5. 按人类审计员的顺序复核

1. **重建来源单元。** 先看原页、完整表格、列标题、分组线、图注、脚注及邻段，再看索引 chunk。标出首次发生缺失、错行、归属错误或上下文截断的位置；不要用模型提取结果倒推原文。
2. **冻结规则边界。** 明确一个规则结束在哪里，哪些条目是分支、计分项、例子、例外或适用条件。记录原文位置与逐叶位置；原文含糊处标 `unresolved`，不补成自己认为合理的临床规则。
3. **写两份无公式转述。** 英文逐句保留 must / may / either / all / at least / unless，中文独立写成“在 A 中，若……则……；未满足时允许……”。两份转述须保持原文措辞强度，并注明“诊断、分类、支持、排除”是哪一种。
4. **先盲法形式化来源。** 在不看病例金标及模型结果时，给出目标概念、完整 AST、每条边的方向和所需适用范围。需要医学解释或来源无法唯一确定的条目先隔离。完成来源判断后再对照模型 AST，防止为解释成败而事后选逻辑。
5. **用反例查错。** 对小组枚举真假赋值，特别查：一真一假时 AND/OR 是否不同；只满足一个替代路径是否足够；计数少一项是否仍可判；有扣分项但总分仍过线是否被误排；充分路径失败时 D 仍可能为真吗？未知变量是否被错误补成阴性？
6. **再盲法匹配病例。** 暂时遮住金标，逐项记录原始事实跨度、时点、主体、单位和 true/false/unknown/inconsistent。区分明确否定、未提及、未检查、检查不适用、不同时间或不同家庭成员。不存在证据时不能由“病例应该包含”补全。
7. **最后打开金标并追踪后果。** 对照实际匹配器、引擎输入、组状态和结论，定位第一次分歧。分别重放“只修来源”“只修 AST”“只修病例赋值”“只修执行语义”；冻结其他输入。若不能隔离，标多因素，不能宣称单一因果。
8. **人工复审争议。** 第二审阅者复核的是原文含义及病例证据，不只是同意第一位的错误标签。保留原判、异议、裁决理由、仍不能确定的项；没有独立医学审阅时直说，不以多次 LLM 自审替代。

逐条账本最少保存：来源锚点、来源转述、人工 AST、机器 AST、差异类型、首次损坏阶段、病例逐叶证据、原/修正组状态、原/修正结论、可归因程度、残余不确定性。组缺失、组语义错误、原子语义错误、匹配错误与执行错误可以共存；不要强迫一个条目只占一个互斥类别。

## 6. 本轮参照检查及实际边界

运行 `python reference_semantics.py` 会就地生成确定性 JSON：检查有符号叶、嵌套连词、计数边界、共享叶依赖、三种蕴涵方向、未知/冲突停止、适用范围、重复计数拒绝、评分类型拒绝和规则身份变更，并保存反模型。它用于识别**生产输出与最小语义承诺不一致**，通过这些检查不等于通过临床验证。

这不是建议全面重写诊断系统。最小可交付修复的次序应由实际审计证据决定：先阻止无认证硬动作及不支持结构的静默降级，保留原始组与失败原因，再对已人工核准的小组做精确重放。软排序怎样使用规则仍需独立评估；重复规则不应增加独立证据量，硬命题也不能仅因“组较大”而被拆成多个普通权重。
