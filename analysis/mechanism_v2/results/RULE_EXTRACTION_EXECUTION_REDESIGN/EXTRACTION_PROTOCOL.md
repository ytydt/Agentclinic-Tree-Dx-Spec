# 可比较的源规则抽取协议与提示模板

状态：研究设计，2026-09-06；模板未用于本轮新API实验。它们是下一轮可冻结的候选协议，不是已验证的最优提示词。表示字段以 [SEMANTIC_CONTRACT.md](SEMANTIC_CONTRACT.md) 为准。

## 1. 输入包与任务隔离

离线知识抽取以 `SourceUnit` 为输入：内容哈希、稳定文档标识/版本、章节祖先、原文跨度、表头/行/脚注、必要邻文、来源完整性及目标任务类型。来源中的疾病名称是规则内容；当前病例金标、模型排名和“请帮助某候选”不进入源规则发现阶段。

旧pipeline的focus依赖仍保留为对照臂；不要把无focus的源级抽取与有focus的旧调用混成同一分母。若在线预算只能抽特定主题，需保存focus及该主题覆盖范围，明确遗漏终点是全源规则还是任务相关规则。

每个阶段输出均保存原始响应、模型/provider/参数、完整prompt及哈希、输入哈希、schema/编译版本、调用/失败/重试与token用量。缓存成功空结果和请求失败分不同状态。重试不得覆盖第一次失败的账本。

## 2. 阶段A：来源先行的规则清单

输入：完整SourceUnit，允许返回“没有可用目标规则”。输出：独立源规则清单、非目标内容、源缺口和歧义；这一步不受输出条数奖励。

可冻结模板：

```text
你在建立可追溯的指南规则清单。仅使用给定SourceUnit，不使用患者病例、候选排名或外部知识补全。

先识别每一个具有独立条件和结论/用途的规则单元。规则组、完整评分表、工作流分支都作为整体保留；同时记录其子式跨度。

对每个单元记录：
1. 原文位置、父标题、正文及必要表头/脚注/例外的引用位置。
2. 原文所指对象与任务：诊断、分类、关联、评分、建议检查、治疗、资格/路径、推断权限或背景。
3. 条件控制的结论/动作，以及原文是否明确必要、充分、排除、概率/典型或未说明。
4. 人群、人物角色、部位、时间、方法和条件适用范围。
5. 连词、量词、计数、否定与例外的原文触发跨度。
6. 成员全集是否可见；缺失表头、邻页、脚注或未知量化域时说明缺口。

不要把疾病别名当患者症状，不把检查名称当阳性结果，不把鉴别名单变成方向性反证，不把负评分变成排除疾病。
不要为填字段而猜测。源文有多种合理读法时保存歧义；某种结构当前不支持时保存unsupported及原文。
返回清单与范围说明，包括零目标规则的结果。此阶段不生成患者满足状态。
```

验收：先冻结清单再揭示下游输出/病例结果；抽查遗漏、错误拆分、非目标误入及组完整性。模型清单不能自充人工参考，能力评估必须另有独立源清单。 阶段B保留阶段A范围是版本控制，不能掩盖A的漏项：整体忠实保留按独立源清单评价A→D全链，另报固定清单条件下的结构化成绩。漏项返修产生新清单版本；人工参考清单输入只作oracle条件。

## 3. 阶段B：符号与逻辑依赖

输入：源规则、出处及清单。输出：固定类型/角色的符号表和可选解释的递归结构。变量域与根效果分开，不把表面 `all` 自动译为临床必要性。

```text
将已给出的规则单元解释为带来源锚点的结构，不改变清单范围。

先给概念/测量/事件建立符号，声明参数角色、类型和变量域。复用同义概念；父子、病因/表现、不同标本/部位和不同测量不能合并。

建立逻辑依赖：AND、OR、NOT、显式量化、distinct计数、比较和时间关系。每个连接、量词、否定及条件范围均回指原文位置。
说明量化的对象是人、事件、测量、标准类别还是其他集合；记录该域如何得到及是否完整。

根条件与根效果分别输出。叶子仅表示命题，不独立携带对疾病的确认/排除指令。
评分表使用signed_score结构；建议和流程使用动作结构；禁止某种推断使用inference_policy，不将它写成患者疾病真假的物质蕴涵否定。

保留无法裁决的作用域解释；不要按方便执行的默认顺序选择。来源未明示的背景蕴涵另列proposed_bridge，不标成源规则。
```

对比实验必须包含一次性递归IR输出，以检验多阶段是否值得额外成本。固定符号表、人工符号表与模型符号表是不同实验条件；不能用oracle符号条件的成绩代表自动端到端能力。

## 4. 阶段C：确定性编译与不静默修复

编译器检查：

- 子式类型、参数元数、自由变量、变量可达范围、引用循环/未定义引用。
- `logic_profile`、符号签名、背景理论与域/观测完备假设；变换或等价证书只能在相同语义前提下使用。
- 组稳定ID及成员引用；跨窗口局部ID不能合并；shared leaf不删除occurrence。
- 数值区间端点、单位、测量身份、评分正负与互斥档。
- 量化域来源声明及与冻结成员清单的一致性、计数单位、阈值与成员数的一致性；不能仅靠编译器判定原文成员已被找全。
- 根效果与根条件类型；成员是否越权携带动作；同一规则不合意地混入多个疾病主体。
- 来源定位真实存在；源缺口和歧义未被丢掉；“存在出处”不直接升级为“忠实”。

输出 `compiled / invalid / ambiguous / unsupported / source_incomplete` 等结构状态，另有独立的语义审核状态。不要把编译失败统一改成 `feature_of` 或 `any`；不要把缺少n猜成1；不要删一条难条件后宣称已完成组。

这些检查只证明形式合同中的约束。量纲相同的PASP/mPAP、同类型参数交换、完整合法但反转的蕴涵，还要进入下一阶段。 经典二值下的`A∨¬A≡TRUE`在Strong Kleene未知输入下并不保持运行行为；编译简化须以所选profile中的行为保持为准。原IR仍作参照，不能把二值等价证书当作三值患者执行证书。

## 5. 阶段D：源文在场的差异与反模型核验

优先对硬动作、量化范围、例外、评分及多个合理解析启动。输入原文、候选结构、编译诊断和最小区分世界；不只给模型它自己的公式。

```text
审查候选结构是否保持给定原文的意义。原文是参照；当前病例是否答对不是判断依据。

逐项检查对象、关系/动作类型、必要/充分方向、否定归属、连接结构、量词顺序/域、人物与时间范围、数值单位/阈值、例外和组完整性。
对于每个候选解释，说明给定区分世界是否符合原句；引用能决定差异的原文跨度。

结论仅可为：有来源支持的解释、明确不等价、来源含糊、证据不足/需补源、超出可审范围。
不要以两个公式均可执行或多数候选相同代替源文判断。
修订须指出修改的子式、出处及行为差异；保留原版。不能为了让求解器返回答案而删除条件、添加无源前提或偷偷改谓词含义。
```

可信人工参考IR可在明确的logic_profile、符号映射、背景理论及完备性假设下进行形式比较；若求解器只验证经典完整解释，须另检验三值与冲突状态下的行为保持，不能跨语义复用证书。没有参考时，LLM对反模型的裁决仍只是模型判断。必须在新的来源样本上测审阅器的漏检、误报和修坏率。人工审核可作为高风险研究版本的准入来源，但与自动版本分开报告成本及效果。

## 6. 患者桥接独立执行

患者事实编译另有输入包，保留原始vignette的事件关系；抽取模型不能反过来根据指南需要补患者事实。它至少输出人物、事件、概念、取材、部位、方法、value/unit、时间、极性和不确定性。

join先检查身份和范围，再判断数值/状态。嵌入只提议映射，不具有“相似所以为真”的权限。每次连接保存接受/拒绝原因及两个源跨度；无匹配、阈值无法比较、明确阴性、冲突是不同状态。

与规则模型使用同一模型并不意味着一致性正确。评价要有自动IR×自动facts、人工IR×自动facts、自动IR×人工facts、人工IR×人工facts，并固定候选、执行器和自动join版本。四格若仍使用自动join，只能解释该join条件下的IR/facts效果与交互；双人工输入格也可能被join破坏。要估计可信输入的执行上界，还需给相应参考单元提供独立核验的join映射，不能把自动连接错误算作源IR或facts错误。

## 7. 成本、缓存和修复账本

为每条规则保留版本链：source→inventory→symbols→IR candidates→compiler outcome→semantic verdict→admission。变更任何prompt、模型、作用域、极性、阈值、概念映射、编译规则、logic_profile、背景理论或完备性假设均应改变对应缓存身份；旧结果保留历史可读性，不原地重写。

每次修复记录四类结局：错→对、对→错、错→另一错、不变；另外记录来源歧义和无法裁决。按错误槽位和完整规则同时统计，不能靠修好一个连词掩盖新引入的方向错误。

多阶段pipeline与单轮模型至少作等调用预算和等token预算两种比较，并单列实际壁钟、外部工具、人工核验和缓存收益。不同provider或模型快照不能隐含视为同一抽取器。固定11例只作回归，不用于选择最有利的提示词后再宣称泛化。

## 8. 不能让该协议“看似成功”的捷径

不得用当前金标挑选只支持目标的规则；不得删掉无结果窗口或所有失败调用；不得用生成原子行作源规则分母；不得只评可执行输出；不得把拒绝全部组当作低错误率成功；不得把人改后的IR记为自动提取；不得用当前vignette唯一答案替代规则多查询测试。

协议真正需要证明的是：在固定来源和明确任务范围下，完整忠实保留提高，严重语义错误下降，同时有效规则覆盖及后续患者执行没有被牺牲到不可用。具体门槛与统计口径见 [研究路线](RESEARCH_ROADMAP.md)。
