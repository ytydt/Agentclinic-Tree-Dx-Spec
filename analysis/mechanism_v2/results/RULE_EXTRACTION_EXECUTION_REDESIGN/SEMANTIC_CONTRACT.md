# 规则抽取与执行的语义契约（设计稿 0.1）

日期：2026-09-06。状态：**设计提案，未进入生产执行器，未证明诊断性能提升**。本文件、`ir_examples.json`、`acceptance_vectors.json` 和 `validate_contract_examples.py` 构成独立的表示与验收空间。所有 JSON 中的疾病目标、逻辑标准、数值阈值、计分权重和时间窗均为 **synthetic fixtures**，不是完整或真实的医学诊断标准。指标身份、组织/血、患者/家属的区分用于复现审计揭示的错误类型，不宣称建立新的临床规则。

## 1. 一等公民是整条 Rule，不是命中原子的列表

一个 Rule 统一拥有目标、适用范围、结论效果、递归条件、来源和完整性。其条件可以递归嵌套，但内部节点和原子只能表达条件；**不得各自携带诊断 `relation`、`target` 或 `effect`**。若原文确实给出了多个结论，应形成有共同来源的多个 Rule，或显式的多结论结构，不能让执行器根据原子标签自行拼出组效果。

| 字段 | 必须表达的内容 | 不能用什么替代 |
|---|---|---|
| `rule_id` / version | 单一源规则单元的稳定身份及编译版本 | 跨索引不稳定的 chunk gid |
| `target` | 概念身份、疾病/流程对象类型、粒度、实体角色 | 模糊字符串相似度最高的候选 |
| `effect` | 该**整个条件**成立或不成立时，允许什么类型的结论 | 混在原子上的 `supports/excludes` |
| `applicability` | 人群、场景、时段、取样/测量条件等的独立表达式 | 默认所有患者、所有时间均适用 |
| `condition` | 保留变量与作用域的递归 AST 或等价作用域图 | 原子袋、仅有 `all/any/at_least` 的槽位 |
| `provenance` | 文档版本、实际源窗、页/段/表/行锚点、原文哈希、提取焦点、审核状态 | 只有标题，或模型生成的解释文字 |
| `completeness` | 源窗、成员清单、逻辑范围、目标解析各自是否完整 | “成功返回了 JSON” |
| `authority` | 哪个依据批准该效果为硬动作；许可适用范围 | 高置信度、很多相似规则或一次 LLM 自评 |
| `semantic_context` | 逻辑 profile、符号签名、背景理论、域/观测完备假设及冲突策略 | 只写“经求解器证明等价” |
| `deduplication` | 源规则身份、语义等价/派生关系、重复曝光记录 | 把重复抽取的每行都再加一次分 |

本稿 JSON 只展示这些字段的最小实例；`source_window_hash=null` 等仅因示例为手工合成，不能作为生产来源合格条件。真实 Rule 的来源完整性必须指向实际读入窗口，不能用数据库里“某处存在完整版”代替模型确实看到的内容。新旧差量审计已经确认同标题改窗、焦点变动和保留段落在不同上下文中产生不同结果，因此提取焦点和实际 payload 都属于谱系的一部分。[差量来源报告](../V2_INDEX_DIFFERENTIAL_AUDIT/RETRIEVAL_DELTA.md)。

## 2. 逻辑形状与效果方向是两个独立维度

定义疾病命题为 `D`，Rule 条件根为 `C`。以下是设计中的动作合同，不是把所有逻辑公式都交给一个任意推理器做反向推导。

| `effect.kind` | 源文若忠实支持时的形式意义 | 允许触发 | 不允许触发 |
|---|---|---|---|
| `sufficient_for_target` | `C → D` | `C=TRUE` 可申请确认 D | `C=FALSE` 不能排除 D |
| `necessary_for_target` | `D → C` | `C=FALSE` 可申请排除 D，须通过第 6 节门槛 | `C=TRUE` 不能单独确认 D；`UNKNOWN` 不能排除 |
| `sufficient_for_exclusion` | `C → ¬D` | `C=TRUE` 可申请排除 D | `C=FALSE` 不能确认 D |
| `defeasible_support` | 非刚性证据关系 | 一次有界支持或反证输出 | 不凭命中次数升级为刚性结论 |
| `signed_score` | 规范化评分定义 | 原尺度的总分或区间 | 自动当作概率、似然比、确诊或排除 |
| `not_allowed_to_exclude` | 指定证据/方法缺少排除 D 的权限 | 写入推断权限状态及适用范围 | 写成疾病命题 `¬(C → ¬D)` |

必要与充分标签必须来自原文语义审核。把 `C → D` 改成 `D → C` 并非微小 relation 改名，而是改变允许的反例与临床动作。来源只说“可以提示、建议进一步检查”时，不能因为条件精确就提升为必要或充分诊断标准。

“不允许用 X 排除 D”是关于推断行为的元规则；它本身不证明 D 或 ¬D。经典逻辑中的 `¬(C → ¬D)` 等价于 `C ∧ D`，明显是另一种疾病/条件断言。V43/V48/V54/V55 分别检验权限和真值层，不将二者混用。

## 3. 表达式：递归组合、变量绑定与独立计数

布尔表达式的最低要求为 `and(children)`、`or(children)`、`not(child)`；内部蕴涵可保留 `implies(antecedent,consequent)`，不丢掉源方向。数值、时间、原子观察和量词结果都是带类型的布尔条件；评分结果是另一种类型，不能无阈值/授权转换便成为布尔标准。

`forall(var, domain, body)` 和 `exists(var, domain, body)` 必须声明变量、域、域成员身份、绑定角色和嵌套位置。自由变量拒绝编译；本稿还拒绝变量遮蔽，以降低审核难度。真实实现可允许严格定义的 alpha-renaming，但不能靠同名字符串隐式绑定。以下两个公式不是同一个组：

```text
forall p in Persons: exists e in Events: linked(p,e)
exists e in Events: forall p in Persons: linked(p,e)
```

V10/V11 使用同一个完整有限模型：每个人都有自己的事件，但没有全体共享的一个事件，前式真、后式假。仅有一个 `quantifier=all` 槽位无法表达此差异。

计数单独定义为 `countDistinct(var, domain, distinct_by, body, comparison, threshold)`，不把它伪装成所有/存在量词。`distinct_by` 必须是指南所数的**判据类别、临床事件或域成员身份**，而不是检索行号、模型原子行号或一律使用 `fact_id`。

- 同一 echopraxia 类别被重复措辞抽取，仍只有一个类别的见证。
- 该见证不能自动成为另一个 echolalia 类别的见证；每个计数类别需有自己的可追溯支持。
- 一个复合观测可以明确包含两项独立观察，因此允许同一 `fact_id` 下两个不同 `assertion_id` 支持两个标准。**不全局禁止同一事实来源支持多项合法标准。**

这里的两个类别仅用于对应审计中的区分错误；本稿的计数阈值是合成值，并非重述完整紧张症标准。V18–V23 检查类别去重、缺失见证、复合观测与不完整域。

CNF/DNF 是布尔意义和求解时的可选转换，不必是 LLM 抽取时强制展开的表面形式。分配展开可能指数膨胀；**在经典二值语义下**，完整定义式 Tseitin 编码需保留辅助变量定义和根式，使原式与辅助变量存在量化后的编码对应。不得只看到“等可满足”便把每个辅助原子当成独立临床证据。[形式语义分报告 §6](../FAITHFUL_RULE_EXTRACTION_LITERATURE_REVIEW/semantic_parsing_review.md)。嵌套 AND/OR 和个体量词仍可属于一阶逻辑，不应误称为高阶逻辑。

**二值等价证书不能直接授权本合同的三值 IR 简化。** 例如经典逻辑中 `A OR NOT A` 等价于 TRUE；但 A 未观测时，Strong Kleene 对前式求值得 UNKNOWN，对后式求值得 TRUE。V56/V57 是同一未知赋值的反例对；V58/V59 保留完整二值赋值的对照。CNF/DNF 转换、子式化简和辅助变量编码都须按所声明的实际执行语义验证，不能以“属于标准逻辑变换”为由绕过这一要求。

任何编译等价/派生证书至少绑定：输入与输出 IR 哈希、`logic_profile_id`、`symbol_signature_id`、`background_theory_id`、域完整性与观测完备假设、冲突策略及所用转换规则。证书不得跨 profile 或背景假设复用。面向二值求解器的导出可用于其声明范围内的反例搜索，原 IR 继续按三值合同运行；若要让导出结果改变运行 IR，必须另行证明所需的三值行为、冲突状态以及来源/见证映射被保持。单纯保存真值等价也不足以授权丢掉诊断动作所需的来源或权限。

## 4. 三值与冲突：未知不能在投影列表时消失

每个布尔结果至少为 `{value: TRUE|FALSE|UNKNOWN, conflict: none|present}`，另附证据见证和求值轨迹。`UNKNOWN` 表示现有信息不能决定真或假；`conflict=present` 表示有关证据/绑定发生尚未解决的冲突。两者不可混为一个低置信度值。

本稿例子采用 Strong Kleene 三值表。缺失观察为 UNKNOWN；明确阴性可为 FALSE；同一时段、主体、指标及条件下的正反断言为 UNKNOWN 加 conflict。病例说“安排了某项检查”只产生一个检查事件，不能变成该结果为真。把“没有记录阳性”当成阴性必须有明确的封闭性许可，不能作为默认行为。

| A | B | A AND B | A OR B |
|---|---|---|---|
| TRUE | UNKNOWN | UNKNOWN | TRUE |
| FALSE | UNKNOWN | FALSE | UNKNOWN |
| UNKNOWN | UNKNOWN | UNKNOWN | UNKNOWN |

`NOT UNKNOWN = UNKNOWN`。**允许可靠短路**：AND 有确定 FALSE 时根可为 FALSE，OR 有确定 TRUE 时根可为 TRUE。禁止的是绕过根的运算规则，不是要求所有叶子永远都已观测。V05/V06/V41/V42 将二者分开。

冲突状态独立传播。本稿采用保守动作策略：规则中仍有相关未解冲突时暂不发出硬动作，即使三值根因另一支路已经可决定。V09/V45 展示 TRUE 与冲突并存。后续实现可以用经核验的最小证明切片判定某冲突与本次结论无关，但这必须有明确依据；不是遇到冲突就让加权多数盖过它。

源结构完整性、域完整性和患者观测完整性必须分别记录：

1. **源/成员完整性**：原准则列有多少项、表是否完整、括号或例外是否缺页。未知结构的局部原子求值只算 preview，不签发已知根结论。
2. **域完整性**：患者、时间点、检查或类别的全部相关成员是否已枚举。空观察列表不等于完整空域。
3. **观测完整性**：已知成员的事实值是否齐全。已枚举的十二项里只有两项被观察，其余十项必须留为 UNKNOWN。

CQL `AllTrue` 等列表算子有自己的 null 语义；本合同不允许先过滤未知，再把空/残缺列表的聚合真值当成组满足。[临床标准分报告](../FAITHFUL_RULE_EXTRACTION_LITERATURE_REVIEW/clinical_standards_review.md)。

对不完整域采用以下有限信息规则：`forall` 见一个 FALSE 即可为 FALSE，其余全 TRUE 但域未闭合则 UNKNOWN；`exists` 见一个 TRUE 即可为 TRUE，否则域未闭合则 UNKNOWN。完整空域的经典 forall 为真，但医学应用还必须证明适用人群/所需非空条件；V16 是纯逻辑边界，不能直接变成诊断动作。

计数保留确定下界 L 与可能上界 U：完整域中 `L=真类别数`，`U=L+未知类别数`；未闭合且无可信基数界时 U 无穷大（JSON 用 `null` 加语义约定表示）。至少 k 在 `L≥k` 时可确定真；至多 k 在 `L>k` 时可确定假；精确 k 需要足够收紧区间。不能把未观察项从域里删除。**患者域未闭合但已有充分见证**和**源准则结构未完整提取**是不同情况：前者可允许单调结论，后者不能声称已知了完整组的意义。

## 5. 类型化条件与计分，防止桥接改变对象

### 数值

比较签名至少包含测量主体、`metric_id`、单位、采样/部位、方法、参考范围/条件和时间位置。单位转换只能在维度和转换条件成立后做；同单位不证明同指标。V26–V29 使用合成阈值检验 `mean_PAP`、`PASP` 和 `TAPSE_over_PASP` 不可互换。验证器只实现 mmHg/kPa 的演示转换，不是完整 UCUM 服务，也没有临床阈值知识。

### 时间与角色

时间条件必须保留事件身份、顺序、区间边界及参照点，不能只抽出一个天数。V30/V31 改变顺序便改变真值，V32 无日期为未知。血液与组织结果、患者与家属结果通过不同参数/限定绑定，不能由词面相似合并。上述字段还必须由事实编译器保留，只有规则端加槽位不足以阻止桥接损失。

### 有符号评分

评分规则声明原尺度、独立特征身份、正/负权重及汇总方法。重复来源的同一评分特征不新增项；不同特征是否可同时计分由原量表决定。负权重不取绝对值，不当作错误排除项过滤；未知特征贡献一个区间而非固定零。V33/V34/V46/V53 是合成评分，不能被解释为真实 CPVT 量表。

评分输出与诊断动作分层。只有原文另有经核验的阈值/分层定义时，才能建立引用该评分版本的独立 Rule；量表分值不能无校准地跨疾病相加，更不能把一组原子按命中条数拆为多份加分。

## 6. 从逻辑结果到硬动作的授权门槛

一个硬动作至少要求：

```text
Rule 语义与目标审核通过
AND 来源窗口、准则成员、逻辑作用域均完整
AND applicability = TRUE 且无相关未解冲突
AND 根求值已决定，所用见证具有明确观察依据
AND 此 effect 在此 scope 被批准为硬效力
AND 无适用的推断权限禁令
```

对 `necessary_for_target` 的 FALSE 还须证明这是**决定性反例**而非缺失、域截断、阈值错绑或模糊别名失败。该门槛不要求所有无关观察完整：若必要合取 `D→A∧B` 中 A 被明确否定，A 就是可用反例；B 未知不会使这个反例失效。V36 与 V37/V38/V39/V50 分别检查反例、未知、范围、授权与决定性。

必要合取允许经认证生成派生 Rule：由 `D→(A∧B)` 可推出 `D→A`。这不是允许任意原子携带硬关系。派生 Rule 必须保留父规则证明、目标、来源、范围和权限，并在父规则被修订时失效；`S_NECESSARY_A_DERIVED` / V47 展示这种结构。必要析取不能同样推出每个分支必要；充分合取也不能推出每个叶子充分。

一个 Rule 根最多输出一次效果。重复 chunk、改窗重复、同义原子或同一规则被不同焦点抽取不应重复计分；事实见证用于说明为什么根成立，不是额外的排名票数。若支持与排除来自不同有效规则而冲突，应建立规则间冲突记录，不能由原子数量决定胜负。

权限必须限定到**当前目标、证据/检查方法、推断动作及适用范围**。例如某检查不得用于排除某病，并不禁止另一项独立且获授权的证据排除该病。验收器中的 `context.exclusion_permission` 只是调用者已经完成上述匹配后的合成结果标志；它不实现权限规则的适用性解析，也不代表患者或疾病的全局“永远不能排除”开关。

## 7. 谱系、兼容与不确定解释

真实部署需分别保留 `raw_source → exposure_payload → raw_model_output → parsed_IR → audited_IR → bound_facts → evaluation → action`，每层版本与哈希独立。缓存键至少包含实际源窗、焦点、提示词、schema、模型/参数和解析器版本；执行缓存另包含事实编译与语义合同版本。相同 gid 不是跨索引同输入，标题相同也不证明内容相同。

对不能确定的连词、量词范围或方向，应保留带源锚点的候选解释/未决槽位，阻止自动晋升为硬规则；不要在 parse repair 阶段静默补一个默认 AND 或 excludes。生产迁移时也不能给历史只有 quantifier 的组统一补 AND：先区分真实 all/any/计数、枚举说明、评分项和不完整表格，无法确认的记录保持未审核状态。

该合同借鉴 ACE 的明确解释约定与来源锚点、MRS 的作用域保存、PMB 的核验状态、约束解码的结构/绑定检查，以及独立形式规格下的反例验证；这些方法各自的保证边界见第二任务。合法 AST、可求解和 round-trip 近似一致都不等于指南保真度已获证明。[文献综合报告](../FAITHFUL_RULE_EXTRACTION_LITERATURE_REVIEW/REPORT.md)。

## 8. 本设计产物的实际验收范围

运行：

```bash
python analysis/mechanism_v2/results/RULE_EXTRACTION_EXECUTION_REDESIGN/validate_contract_examples.py
```

脚本只读取同目录的两个 JSON，检查 Rule 必要字段、固定演示 profile、原子无独立效果、变量绑定、评分类型和重复特征，并核验示例中必要合取派生的父引用、合取消解形状及范围/权限/语义上下文等继承字段；随后对**手工给定的有限合成事实赋值**计算期望结果。它只支持这里声明的 K3/冲突演示语义，不会验证一般转换证书，不会读取现行规则缓存、修改生产代码、请求模型或重新评价 11 例。

它是一个小型例子一致性检查器，**不是**完整 FOL 证明器、临床事实绑定器、来源蕴涵检查器、患者安全认证或生产执行器。其 `fixture_hard_effect_authorized` 只模拟验收门槛；所有示例均显式 `clinical_use_authorized=false`。通过只能说明这些合成向量与所写设计自洽，不能说明源文→IR 正确，更不能说明 MRR 提升。

当前覆盖：CNF/DNF 及深嵌套；量词顺序、开放域与反例；未知/冲突；经典二值等价与三值求值的差异；类别独立见证和重复；量纲及指标身份；组织/血、患者/家属；时序；有符号分数；充分/必要方向；不完整源组；元权限；合法必要子规则派生；非法原子效果和自由变量。完整生产实现仍须通过源规则级人工参照、事实绑定审计及冻结反事实实验，不能以这些例子取代第三任务主报告的实证路线。
