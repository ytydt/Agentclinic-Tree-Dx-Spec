# 这个目录在讲什么（面向初次阅读者）

共用术语见 [../READER_GUIDE.md](../READER_GUIDE.md)。本文只讲这个目录独有的东西。

## 一句话

前面几份审计诊断出了病。这个目录开药方：**把「一行断言身兼数职」拆开**，改成四个可以分别审查的对象。

**注意：这是设计方案，一行生产代码都还没改，也没有声称能提高诊断准确率。**

## 核心诊断：一行断言干了四件互相冲突的事

现在的 `subject + predicate + relation + group_id` 一行，同时被当作：

1. 来源知识（原文说了什么）
2. 病例匹配对象（拿去和病人对）
3. 硬动作依据（据此淘汰或确认候选）
4. 评分票（加分）

这四件事的正确性标准完全不同，混在一行里就没法分别验收。方案是拆成四个对象：

| 对象 | 装什么 |
|---|---|
| **RuleUnit** | 这条源规则的稳定身份、针对哪个病、什么用途、适用范围、出处、完整性 |
| **SemanticIR** | 逻辑表达式本身：递归的 AND/OR/NOT、变量绑定、量词域、数值与时间含义 |
| **EvidenceRecord** | 病人这边的事实：事件、测量值、单位、标本、部位、角色、时间、原文锚点 |
| **DecisionProof** | 哪些证据满足了哪些子式、根表达式是什么状态、**为什么**允许对这个目标执行这个动作 |

## 需要解释的专用说法

| 说法 | 平实解释 |
|---|---|
| **IR（中间表示）** | 介于「原文句子」和「可执行代码」之间的一种结构化形式。 |
| **一等规则（first-class rule）** | 规则本身是个独立对象，有自己的 ID、范围和效力；而不是把效力挂在每个成员身上。 |
| **量词域（quantification domain）** | 「十二项里的三项」——这个「十二项」到底指什么集合。审计发现例 522 只抽到了窗口尾部的 4 项，却保留了数字 3，等于**用 4 项冒充 12 项的全集**。 |
| **Strong Kleene 三值逻辑** | 真 / 假 / **未知**。这是本方案的关键选择：经典二值逻辑里 `A ∨ ¬A` 恒等于 TRUE，但**病人没做这项检查时它应该是 UNKNOWN**。用二值逻辑化简会凭空制造出「条件已满足」。 |
| **反模型（countermodel）** | 一组具体赋值，使原文规则和抽出来的规则真值不同，用来严格证明两者不等价。 |
| **logic_profile** | 每张「等价性证书」必须绑定它假设的逻辑体系、符号签名、量词域和观测完备性假设，**不能跨体系复用**。 |
| **短路（short-circuit）** | AND 遇到确定为假就可以直接判假。方案允许这么算**根**的真值，但强调这**不等于**「任一叶满足就算整组满足」。 |
| **推断权限约束** | 「不要用 EEG 来排除癫痫」这类句子。它约束的是**允许使用哪条推理路径**，不是在断言病人的状态。若按经典逻辑写成 `¬(EEG→¬癫痫)` 再化简，会得到「EEG 阳性且患癫痫」——**凭空断言了患者状态**。 |
| **三种完整性** | ①**来源完整**（表头、脚注、例外齐不齐）②**规则域完整**（「十二项」的全集有没有）③**患者观测完整**（哪项明确真/假、哪项没测、哪项冲突）。三者必须分开记录。 |
| **conflicted 状态** | 两条都合格的硬规则给出相反结论时，保留两条证明进入「冲突」状态，**不允许**用「确认条目更多」或「软分更高」来压倒它。 |

## 几个方案里明确禁止的做法（都对应真实发生过的错误）

- ❌ 缺 `n` 就猜成 `any`
- ❌ 缺失的评分项统一补 0 分（**零分、未测、不适用是三件事**）
- ❌ 把负分项（−1、−2）当成逻辑排除
- ❌ 把「分值 2」读成「至少满足两项」
- ❌ 把截断的列表当作完整的组
- ❌ 用相似度当作「满足证明」（相似度只能用来**生成候选**）
- ❌ 让父类候选靠包含匹配抢走亚型的证据（例 56）
- ❌ 未经授权就把组的每个成员当独立硬判据

## 抽取流程改成四步

1. **来源规则发现**——先完整读原文，独立列出有哪些规则。**不能先看金标或排名再回头找支持句。**
2. **概念与依赖图**——识别实体、角色、连词、量词、例外的跨度，保留歧义读法。
3. **受约束编译**——固定 schema 和符号签名，检查变量闭合、域、量纲、根类型。**不合法就拒绝编译并记录原因，不偷偷改 `all`、阈值或 relation。**
4. **语义对照**——原文在场，用求解器比较候选结构和最小区分输入。NLI 和 LLM 评审只能当**受测的辅助**，不能当独立真值来源。

## 读这份设计时的边界

- **尚未部署**，未声称提高临床性能。
- `validate_contract_examples.py` 只验证**设计产物和受限的合成语义片段**，它不是生产引擎，**不证明原文忠实性或临床有效性**。
- 11 个病例和既往来源样本都是**开发材料**，泛化收益必须由后续独立实验检验。
- 方案借鉴了组合语义、受控语言、约束解码、临床可计算指南（CQL/FHIR）等思路，但**没有把任何单篇研究说成现成解法**。特别指出 CQL 的 `AllTrue` 会忽略空值，**不能直接用来实现本方案要求的「已知完整成员均满足」**。

## 一条很值得注意的提醒

方案自己说：只修一条排除方向、换成递归 JSON、减少重复票，**仍然可能通过其他通路破坏诊断**。因为错误不必有直接分值就能影响排名——不合格的行可以先进 `claimants` 改变别人的票权，裸鉴别列表可以通过 L4 处罚其他目标。

而且：**修复完整实体绑定甚至可能让旧的代理指标下降**，因为旧的 7/11 里有三个是父类/组件终点，且错误否决曾经压住过高分干扰者。
