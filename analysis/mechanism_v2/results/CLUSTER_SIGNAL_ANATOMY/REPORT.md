# 集群信号为何不转化：解剖报告

探针：`analysis/mechanism_v2/cluster_signal_anatomy.py`（**零 LLM 调用**，只读冻结工件）
机读结果：[`anatomy.json`](anatomy.json)
群体：400 例 MCR（`mcr_v1` 100 + `mcr_v2` 100 + `mcr_200b` 200），3500 个候选，166 例池可达
端点：冻结 `ClinicalEndpoint`，`drop_conflicts()`，`complete_equivalent`
证据宽度用 `support_fact_ids` **精确**连接冻结 fact ledger（非 Q9 的子串模糊匹配）

---

## 0. 结论

集群信号**不是假的，也不是被埋没的**。它真实、在病例内成立、且有真实上限空间。
它不转化的根因是三件事叠加，每一件都单独致命：

1. **分辨率太粗**：在决定性比较中有 **42.7% 完全平局**——它对该选谁无话可说。
2. **残余价值为负**：当它与生成顺序分歧时，它只在 **66/156 = 42.3%** 的情况下正确。
   **用它去覆盖位置判断，比抛硬币还差。**
3. **它是生成器已发射的一个更细信号的粗投影**：前 3 个候选平均 1.1675 个高特异组，
   靠后 0.7948。生成器的输出顺序**已经包含**集群信息，且还包含更多。

因此"更用力地提取集群"这个方向从一开始就没有增益可拿：
唯一能超越现任的路径是把信号**变细**（打破那 42.7% 平局），
而 G1 的两个 prompt 没有把它变细，只是把候选集**变了**——
改变率 0.72 / 0.93，而 ledger 组数只动 +0.09 / +0.04。

---

## 1. 先排除一个我自己的假设：这不是组间/组内错觉

我最初的怀疑是 Simpson 式的：池内单调性来自**病例之间**的证据丰度差异，
而选择器只在**病例之内**比较，所以信号不可用。**这个假设被否证了。**

**组间成分几乎为零，甚至轻微反向：**

| | 池可达例 | 不可达例 |
|---|---:|---:|
| 每例候选 `n_high_groups` 均值 | 0.9027 | 0.9360 |
| 每例**可用**高特异相关组数 | 2.4217 | 2.3333 |

两列基本持平。高特异证据更多的病例并**没有**更容易可达。

**组内成分很强。** 把每个候选的 `n_high_groups` 减去其所在**病例的均值**，
只看病例内偏离：

| 偏离病例均值 | 候选数 | 完整率 |
|---|---:|---:|
| < −1 | 78 | **0.0000** |
| −1 … 0 | 550 | 0.0745 |
| = 0 | 180 | 0.1222 |
| 0 … 1 | 529 | 0.1682 |
| > 1 | 84 | **0.3452** |

**病例内 4.6 倍跨度**，且单调。所以论文的主张在我们的数据里是**真的**，
而且是在选择器实际工作的那个层级上真的。

顺带确认 Q9 的单调性稳健：改用精确 `fact_ids` 连接后仍单调
（0/1/2/3/4 组 → 0.0289 / 0.0481 / 0.0931 / 0.0991 / 0.1765），
与 Q9 模糊口径的 0.0299 / 0.0541 / 0.0862 / 0.1196 基本一致。
**Q9 的信号不是模糊匹配的产物。**

---

## 2. 根因之一：分辨率不足，43% 的关键比较是平局

选择器唯一能兑现的量是**病例内一致性**：在同一病例中，
随机取一个完整候选和一个不完整候选，信号把完整的那个排在前面的概率。
0.5 表示在选择时刻毫无用处，无论池内关联看起来多强。

| 信号 | 病例内一致性 | **平局率** |
|---|---:|---:|
| `gen_order`（越早越好） | **0.7793** | **0.0000** |
| `n_spans`（原始跨度计数） | 0.6782 | 0.2332 |
| `n_high_groups`（高特异集群） | 0.6638 | **0.4273** |
| `n_groups`（全部集群） | 0.6465 | 0.3144 |

三件事一起读出来：

- 集群信号确实带信息（0.6638 > 0.5）。
- **但它比生成顺序弱**（0.6638 vs 0.7793）。
- **而且在 42.7% 的决定性比较里它完全无法区分**，而生成顺序按构造是全序、零平局。

还有一处值得注意：**`n_spans`（0.6782）比 `n_high_groups`（0.6638）略好。**
也就是说，"去重到不同相关组"这一步集群化处理**反而让信号变差**了——
朴素地数引用了多少跨度比数有多少个独立集群更有用。
这暗示被捕获的其实是**引证量**，而不是**证据独立性结构**。

---

## 3. 根因之二：残余价值为负——覆盖位置判断会输

一致性只能说明信号弱，不能区分"弱但可加"和"被完全支配"。
把比较限制在**集群信号与生成顺序意见相反**的那些对上，就隔离出了
"采用集群信号"唯一可能创造价值的地方：

| 信号 | 分歧对数 | 集群正确 | 生成顺序正确 | **集群胜率** |
|---|---:|---:|---:|---:|
| `n_high_groups` | 156 | 66 | 90 | **0.4231** |
| `n_groups` | 206 | 52 | 154 | **0.2524** |

**每次用集群信号推翻位置判断，都是负期望。** 这就是为什么：

- `n_high_groups_desc` 排序转化 0.488 < `gen_order` 0.5602；
- Q9 的三个混合策略（`skip_to_first_high_ge_1/2/3` = 92 / 82 / 87）全部低于 `gen_order` 的 93。

不是"没调好"，而是**方向本身是负的**。

---

## 4. 上限空间是真的，但被锁在平局后面

必须诚实记录一个与"信号无用"相反的事实：

| | 转化 | 完整例数 |
|---|---:|---:|
| `n_high_groups` 的 **oracle 上界**（平局完美打破） | **0.6687** | 111 / 166 |
| 现任 `gen_order` 实际 | 0.5602 | 93 / 166 |
| `n_high_groups` 实际（生成顺序打破平局） | 0.4880 | 81 / 166 |

**oracle 上界 0.6687 高于现任 0.5602，高出 18 例。** 而且这不是"平局集太宽"的假象：
平局最高集平均 **3.3795** 个候选（池宽 8.5602），
同规模随机零模型只有 **0.4174**，oracle 的**净提升 +0.2512**。
信号确实把完整标签**浓缩**进了它的最高层。

但这份上限空间**取不到**，两道成本各自都超过收益：

- **平局打破损失 111 → 81（−30 例）。** 即使用最好的可用打破器（生成顺序），
  在最高层内部也只能挑对 81/111 = 73%。
- **过滤排除损失 55 例（33%）。** 有 166 − 111 = **55 例**，
  `n_high_groups` 最高的那一层**根本不含**任何完整标签——
  按它筛选会把答案直接扔掉。

净结果：先筛后按生成顺序选 = 81 例，**比单用生成顺序（93 例）少 12 例**。
**作为排序器它输，作为过滤器它把答案丢掉三分之一。**

---

## 5. 根因之三：生成顺序已经吸收了它

为什么位置这么强？因为生成器自己就把证据宽的候选放在前面：

| 候选位置 | `n_high_groups` 均值 |
|---|---:|
| 前 3 个生成的 | **1.1675** |
| 更靠后的 | 0.7948 |

生成器的发射顺序是它**置信度排序**的外化，而该排序**包含集群信息、且不止集群信息**。
这就是此前几份报告里"信号已被生成器吸收"那句话的具体含义——
现在它有了数字：集群信号是那个更细信号的**粗投影**，
投影必然丢信息，所以拿投影去覆盖原信号只能变差（§3 的 0.4231）。

---

## 6. 这如何解释 G1 的失败

G1 的两臂把集群约束加在生成时，结果保留率 0.8955 / 0.8358（均 < 0.90）而关闭。
本报告给出了机制：

要超越现任，唯一的着力点是**把信号变细**——打破 §2 那 42.7% 的平局。
但 G1 的两个 prompt 没有提高分辨率，它们改的是**写出哪些候选**：
改变率 0.7164 / 0.9254，而 ledger 相关组数只动 +0.0915 / +0.0351。

于是干预扰动了**正在承载信号的那个排序本身**（commit 立场，贡献 144/166 独家捞回），
既没有增加分辨率，又付出了召回代价。**这是结构性的，不是调参问题。**

---

## 7. 这份解剖排除了什么，没排除什么

**排除了：**

- "集群信号被埋没、需要更用力提取"这一诊断。它没有被埋没，
  它被**生成顺序支配**（§3、§5），且**分辨率不足**（§2）。
- 用集群计数作为**排序器**（0.488 < 0.5602，分歧胜率 0.4231）。
- 用集群计数作为**过滤器**（33% 的例子里最高层不含完整标签）。
- 我自己的组间/组内错觉假设（§1，已否证）。

**没排除：**

- **论文的主张。** 病例内 4.6 倍跨度（§1）与池内单调性（0.0289 → 0.1765）都成立。
  被否证的一直是**实现假设**，不是现象。
- **那 18 例的上限空间是真的**（oracle 0.6687 vs 现任 0.5602，净提升 +0.2512 over null）。
  它需要的不是"更强的集群压力"，而是**在集群信号最高层内部的一个比生成顺序更好的判别器**——
  这是一个形状完全不同的干预，且 §4 的两道成本（−30 平局、−55 排除）说明
  它必须**同时**解决打破与排除，只解决一头必然亏。本报告不建议直接上手：
  三条既有否证（截断、证据重分配、DA 补全）都表明"在选择层做得比生成顺序更好"本身很难。
- 本结论**不外推**到 DA 族、不外推到 legacy `dc.match` 口径。

**不可写：**

- 不可把 oracle 0.6687 报成"可达增益"。它是**上界**，且实际可达配置全部低于现任。
- 不可把"集群信号带信息（0.6638 > 0.5）"写成"集群信号有用"——
  在已有生成顺序的条件下它的**边际**贡献为负。
- truth tier 是 model-panel sensitivity，非人工根真值。
- `mcr_200b` 在本报告中仅用于**描述性**解剖（零调用、无门槛、无模型选择），
  未用于任何干预的判定；holdout 作为干预留出集的地位不受影响。

## 8. 一处必须披露的过程错误

本探针第一版把 glob 写成 `logs/backbone_v1/*/aphhm_c_multistance_v1/...`，
误纳了 `diagnosisarena` 等其它数据集，得到 800 例 / 7118 候选。
那些切片不在 `SLICE_OF_DIR` 中，端点查不到判定，于是**静默记作不完整**，
把完整率整体压低（0 组 0.0147 vs 正确的 0.0289），并制造出
"精确连接下 Q9 的单调性在 2 组后崩坏"的**假矛盾**。

已修正为 `medcasereasoning*`，并加了一道硬失败：切片未映射时直接 `SystemExit`，
不再静默降级为"不完整"。本报告所有数字来自修正后的 400 例群体。
