## 2. 召回是怎么丢的

两臂丢失的病例高度重叠：

```
两臂共同丢失（5 例）:  19, 67, 134, 142, 143
仅 arm_A 丢失（2 例）:  162, 196
仅 arm_B 丢失（6 例）:  8, 49, 187, 188, 223, 235
```

`arm_B` 丢的 11 例包含了 `arm_A` 丢的 7 例中的 5 例，且额外丢 6 例——
**与 §5 预测一致：`arm_B` 对生成过程干扰更大，更可能不过门。** 这条预测成立。

按 preferred_label 严格口径与 preferred_label ∪ aliases 宽口径，保留数完全相同
（A 60/60、B 56/56），说明丢失不是别名归一化的产物，而是**标签真的没被写出来**。

## 3. 失败模式与事前设防的方向相反

预注册 §4.3／§4.5 加了一道伪造防护，防的是**交差**：模型把同一观察的复述重新标注成
不同组，自报数上升而实际证据宽度不变。**实测不是这个失败模式。**

| 量 | 冻结基线（门内 67 例，n=331） | `arm_A` | `arm_B` |
|---|---:|---:|---:|
| 候选集改变率 | — | **0.7164** | **0.9254** |
| ledger 相关组数均值 | 1.8097 | **1.9012**（+0.0915） | **1.8448**（+0.0351） |
| support_spans 数均值 | 1.9819 | 2.1168 | 2.0000 |
| span 数 > 组数占比 | 0.2024 | 0.2126 | 0.1701 |
| 自报组数均值 | —（基线不自报） | 2.1138 | — |
| `inflation` = 自报 − ledger | — | **+0.2126** | — |

三条读数合起来给出一个清楚的机制：

1. **prompt 咬得过狠，不是没咬。** 改变率 0.7164 / 0.9254 **远超**预测的
   0.20–0.60 / 0.30–0.70。两个干预都真的改写了候选集。
2. **但它们几乎没有加宽证据。** ledger 组数只涨 +0.09 / +0.04。
3. 所以两个干预实际起的作用是**候选集扰动**，不是**证据宽度改善**。
   而按方案 §0 的硬约束，multistance 存在的唯一理由是召回；
   扰动 commit 立场（贡献 144/166 独家捞回的那个立场）就等于拿召回去换一个没兑现的东西。

`arm_A` 的 `inflation` = +0.2126，落在预注册新增预测的 [0.2, 0.8] 区间**下沿**：
自报确实虚高，但 ledger 组数**也**上升了，所以这不是纯交差，而是"轻微真加宽 + 轻微虚报 +
大幅扰动"的混合。**伪造防护本身没有被触发为主因**——它防住了一个没有发生的失败模式，
真正的失败发生在它没有覆盖的那一侧（扰动）。这道防护零成本、事前写入，保留在案；
但必须诚实记录：**它不是这次判定的依据。**

## 4. 一处必须披露的预注册缺陷：§4.3 的锚分母错配

§4.3 把机制判据的锚定在 **2.1442**，该数算在 **dev 全 200 例的 commit 候选（n=992）**上。
但两臂只在 **67 例门内队列**上评分，那里的冻结基线是 **1.8097（n=331）**。
**这是跨分母比较。**

后果是读数会反转：

| 读法 | `arm_A` | `arm_B` |
|---|---|---|
| 对冻结 §4.3 锚（2.1442，dev 全量） | 1.9012 → 判"未上升" | 1.8448 → 判"未上升" |
| 对配对锚（1.8097，同一 67 例） | 1.9012 → **上升 +0.0915** | 1.8448 → **上升 +0.0351** |

讽刺之处在于：§4.3 本身就是为纠正**同一类错误**而写的——它把 Q6 的 1.95（全立场 n=3415）
换成 2.1442（dev + commit n=992），并明写"这个差异足以反转读数"。
**修正只下降了一级，没有下降到最后一级。**

**处理方式：披露，不回填。** `gate.json` 同时输出两种读数
（`ledger_groups_rose_above_baseline` 为冻结判据、
`ledger_groups_rose_vs_paired_gate_baseline` 为配对判据），并标注
`exit_determined_by: "retention"`。

**这个修正不能、也没有改变判定**，理由是结构性的：§4.4 第三行使保留率**单独**决定出口，
机制判据只在保留率过门后用于在"过门"与"允许一次改写"之间路由。两臂的保留率都已失败，
该路由不可达。若这个修正**能**改变判定，那就构成事后调门槛，必须整份作废重做。

**教训（供后续预注册直接引用）：** 判据的基线必须算在**与被评分臂完全相同的病例集合**上。
"同一口径"不只指切片与立场，还指**病例子集**。三次分母错配（Q6 全立场 → dev 全量 →
门内队列）出现在同一条判据上，说明这需要变成一条机械检查，而不是靠写作时留意。

## 5. 预注册预测的逐条清算

| # | 预测 | 实测 | |
|---|---|---|---|
| `arm_A` 保留率 | ≥ 0.90（点估计 0.90–0.97） | **0.8955** | **否证**（差一例） |
| `arm_A` 改变率 | 0.20–0.60 | **0.7164** | **超出上界** |
| `arm_B` 保留率 | 0.85–0.97（有实质风险不过门） | **0.8358** | **否证**（略低于下界） |
| `arm_B` 改变率 | 0.30–0.70 | **0.9254** | **超出上界** |
| `arm_B` 比 `arm_A` 更可能不过门 | — | 56 < 60 | **成立** |
| `arm_A` `inflation` ∈ [0.2, 0.8] | — | **+0.2126** | **成立**（下沿） |
| 若 `inflation` 在区间内**且** ledger 未升 → 交差 | — | inflation 在区间内但 ledger **升了** | **前提不满足，未判交差** |

它们不是"轻轻加一条约束"，而是实质重写了 commit 立场的行为。

## 7. 这个关闭排除了什么，没排除什么

**排除了（在本队列、本契约下）：** 把症状集群作为**生成时约束**加在 commit 立场 prompt 上，
无论采取"支撑须落在 ≥2 个互不重复观察"（`arm_A`）还是"合取须被陈述并排除最强对手"
（`arm_B`）的形式，**都以召回为代价**，且换来的证据宽度增益微小（+0.09 / +0.04）。

这补上了方案 §0 三条路线中的最后一条。四条否证现在构成完整记录：

| 路线 | 判定 | 依据 |
|---|---|---|
| 集群作为冻结 payload 的后验重排 | 否证 | Q9：组去重使转化率 0.355 → 0.307 |
| 集群作为本体接地的知识对象 | 否证（实现层） | Q3/Q4/Q5：综合征查表 0.11%、HPO 精确接地 3.8% |
| 集群作为证据重排 / 打包开关 | 否证 | Q8：打包翻转冠军时 0 例完整 vs 未打包 5 例 |
| **集群作为生成时约束** | **否证（本报告）** | **G1：保留率 0.8955 / 0.8358，两臂均 < 0.90** |

**没排除：**

- **论文的主张本身没有被否证。** Q9 的候选层单调性（高特异性组数 0/1/2/3 → 完整率
  0.030/0.054/0.086/0.120）仍然成立。被否证的是**"这个信号可以被 prompt 诱导出来"**
  这一实现假设。集群信号是真实的，但它已被生成器的置信度吸收（方案 §0），
  而外部施压去放大它会破坏承载它的那个立场。
- **更温和的干预未测。** 两臂的改变率 0.72 / 0.93 说明它们太激进。一个"只在候选已有 ≥2 组
  支撑时才要求自报分组、不要求砍候选"的软版本没有被测。**但按 §4.4 整线关闭，
  不得在本方案内继续投入**；若要测，须另立方案并重新论证为何值得。
- 本结论**不外推**到 DA 族、不外推到 holdout（`mcr_200b` 的 86 例**从未触碰**，
  按 §7 保持未污染），也不外推到其它立场的 prompt。

**不可写：**
- 不可把本门写成"集群干预有效性的确证否定"：本门零面板、单侧，只能检出召回**损失**（§0）。
  它没有测过转化率，因此**没有**关于"集群是否提升诊断完整性"的任何读数。
- 不可把 `arm_A` 的"差一例"写成接近通过（§0）。
- 不可把 §4 的锚修正当作判定依据（§4 已说明其不可达）。
- 不可把冻结面板判定报成人工根真值；truth tier 是 model-panel sensitivity。
- 不可与 DA 族 pooling。
