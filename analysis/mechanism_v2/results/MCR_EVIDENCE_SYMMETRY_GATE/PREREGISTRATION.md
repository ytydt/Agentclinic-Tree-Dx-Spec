# MCR_EVIDENCE_SYMMETRY_GATE_V1 — 预注册

写于 2026-08-21，**在任何在线调用之前**。这是一个诊断门，不是疗效实验：它只判定"逐候选证据分配"这个假设是否值得再花约 1500 次调用。

## 起因与假设

`MCR_SELECTION_LAYER_AUDIT` 用零调用验掉了三条干预（换候选集、改比较器 family-vs-subtype 判据、重排 payload），并把约束定位在**证据分配层**：在 167 例池内可达队列的 63 例选择层损失中，正确候选（C）相对被选中冠军（W）系统性地带着更弱的证据。

| | C（正确） | W（冠军） |
|---|---|---|
| `for` span 均数 | 2.29 | 3.84 |
| C 的 `for` 更少 | 48/63 | — |
| 带 `against` | 42/63 | 28/63 |
| C 有 `against` 而 W 干净 | 21/63 | — |

机制假设：证据由**提出候选的同一次调用**写出（`aphhm_c_batched_concepts_commit.txt` 等 stance prompt 在一趟里既提候选又写 `support_spans`/`contradict_spans`，并被硬性要求"两个候选不能有相同的 support_spans"）。同一次调用内的名额竞争，使生成器给自己最有把握的候选写厚证据、给陪跑候选写薄证据加显式反对。若如此，把证据改成**每候选独立一次、对彼此盲**的对称推导，这种不对称应显著减弱。

对立假设：不对称是**病例本身的性质**——vignette 对正确诊断的支持确实弱于对那个错误对手的支持。若如此，对称重推不会改变不对称，则该层假设被否，MCR 剩余的 63 例是信息上限而非流水线缺陷。

## 队列

167 例池内可达队列中，冻结冠军非 `complete_equivalent` 的 **63 例**（dev = mcr_v1 + mcr_v2 共 26；holdout = mcr_200b 共 37）。每例取两个候选：

- **C** = 该例 registry 中被临床 panel 判为 `complete_equivalent` 的标签（若有多个，取 payload 顺序最靠前者，与审计脚本 `complete_index` 一致）；
- **W** = 冻结冠军标签。

本门不做 dev/holdout 分阶段：它不选择任何超参，只读一个不对称量，因此两侧合并报告，同时分列以便观察一致性。

## 仪器

新增 prompt `src/agentclinic_tree_dx/prompts/aphhm_c_symmetric_candidate_evidence.txt`，输入为 `{vignette, candidate}`，输出 `{support_spans, contradict_spans, why}`。对称性由构造保证：

- 每次调用只见一个候选，不见对手、不见 gold、不见 stance 与生成序；
- C 与 W 用同一 prompt、同一模型、同一温度（0.0），调用顺序不影响结果（无共享状态）；
- 返回的 span 一律过运行时同一逐字校验（`AphhmC._verbatim` 的 `_norm` 归一 + 子串判定 + 长度≥4 + 去重），因此计数与冻结值可比。

模型与冻结臂一致：`meta-llama/llama-3.3-70b-instruct`。

**预算：63 × 2 = 126 次在线调用，零 panel 裁决**（本门不产生新冠军，不需要新的临床关系判定）。

## 端点与判据

主端点是**配对不对称量**，而非绝对计数——对称重推在两侧都可能整体抬高 span 数（单候选调用没有对手可供区分），配对量对这种共同抬升免疫。

| 门 | 量 | 冻结值 | 通过阈值 |
|---|---|---|---|
| **G-A** 支持侧不对称 | `n_for(C) < n_for(W)` 的例数 | 48/63 | ≤ 38/63 |
| | `mean n_for(W) − mean n_for(C)` | 1.56 | ≤ 0.60 |
| **G-B** 反对侧不对称 | C 有 `against` 而 W 干净的例数 | 21/63 | ≤ 12/63 |
| **G-C** 仪器保真 | 通过逐字校验的 span 占返回总数比 | — | ≥ 0.90 |

判定规则，先于结果固定：

- **PASS** = G-C 成立 **且**（G-A 两项均达成 **或** G-B 达成）。→ 证据分配层假设存活，进入完整干预（dev 73 例全池重推约 707 调用，过门后 holdout 约 886）。
- **FAIL** = G-C 成立但 G-A、G-B 均未达成。→ 该假设被否。结论为：正确候选的 vignette 支持确实更弱，MCR 剩余 63 例是信息上限，不应再在流水线内寻找选择层或证据层干预。
- **VOID** = G-C 不成立。→ 仪器不可靠（模型不遵守逐字约束），需修 prompt 后重跑，不得据此下任何机制结论。

## 预测（先于结果登记）

按机制假设，预期 G-A 达成而幅度中等：`n_for(C) < n_for(W)` 落到 30–38/63 区间，均数差落到 0.2–0.6。理由是竞争偏置只是不对称的一个来源，另一来源（正确诊断本身较罕见、vignette 对它的直接线索更少）不会被对称化消除。

反对侧的预测更强：G-B 的 21/63 主要来自"陪跑候选被顺手写上反对理由"，对称调用没有这个动机，预期落到 8–14/63。

同时登记一个反向风险：对称调用因缺少对手参照，可能对**两个**候选都写出更多且更泛的支持 span，使绝对计数上升而不对称不变。若观察到 G-C 通过、绝对计数显著上升而 G-A/G-B 均不动，按 FAIL 处理，并在报告中明确这一形态。

## 不做什么

- 本门**不**重跑选择器，**不**产生新冠军，因此不报告任何 complete/task 端点变化。任何"证据修好之后转化率会涨多少"的说法都必须等完整干预。
- 本门**不**碰冻结日志与冻结 LLM 缓存（只读），产物写入 `analysis/mechanism_v2/results/MCR_EVIDENCE_SYMMETRY_GATE/`。
- 本门**不**用 dev 结果调整任何阈值——阈值已在上表固定。
