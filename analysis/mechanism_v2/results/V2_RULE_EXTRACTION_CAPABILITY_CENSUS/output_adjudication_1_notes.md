## 判定边界

- 忠实软关联不要求诊断充分性。O1-008、009、015、017、029 是描述性症状/类型集合；不把 `feature_of + any` 自动解释成单个症状确诊。
- O1-027 是一个真正的浅层计数组正例：DLB 的 3 个临床域被完整保留，全部 `required_for`，共享 `at_least_n=2`。此处原始输出可以表达来源的同质组效力。它在执行器中是否正确运行是另一个终点。
- O1-019 不能以同样方式辩护：实际提示词明确 `all` 表示每个成员必需，但来源只是特征性表现且承认非典型表现。错误已经存在于原始组语义，不靠执行器异常才成立。
- O1-005 五个心脏疾病各自的 cyanosis 关联正确，但它们是五个目标，不是一组共同行使效力的判据。整组判为曲解，同时明确保留原子的真实性。O1-001/037/049 等则把鉴别候选名本身当作鉴别性临床 finding。
- O1-014/021 的 `treated_by` 治疗备选项以及 O1-032/038 的明确 postoperative/complication 内容属于可溯源非目标知识。不能仅因它们出现在诊断抽取结果里就说临床语义错误或幻觉。相反 O1-018、022、023、025 把随访、器械选择、预防用药或不施救条件改成诊断 `criteria/feature_of`，改变了原来的决策对象。
- 治疗章节不等于没有诊断特征：O1-072 的前位喉口仍是真实的患者解剖发现，判为忠实。机制句也可含有效诊断关联：O1-041 保留“阳光诱发加重”，没有把它误作原发病因。
- 分子名称必须保留改变方式。O1-062 把 `translocations involving SSX1` 压缩为 `SSX1`，不是等价分子发现。O1-047 把 Ras 相关性升级为病因，尽管原文明说病因尚不清楚。
- O1-057 与 O1-086 是直接极性/方向反转：原文要求排除竞争病因/诊断，输出却使用 `excludes + negated`，把竞争诊断不存在当成排除目标病的条件。两者都能找到明确原文祖先，不属于严格无来源虚构。
- O1-013 把 EGPA 加减分程序转成 `any` 组，并将 −3/−1 转为 `excludes + negated`。没有权重槽位是确定性表达能力限制；评分数值不是排除强度，也不是 finding 的阴性状态。输入没有总分诊断阈值，审核没有凭医学记忆补造缺失阈值。
- O1-051 的 33% 是病例间患病表现频率，却进入单病例 finding 的 threshold；O1-036 把 FAA 飞行适任上限与收缩/舒张压两坐标压成高血压诊断阈值。这些属于数值作用域错误，不是数值字符串抄错。

## 来源未决的解决过程

O1-011 初判 `unresolved_provenance`：输入仅 8 个症状条目，唯一可用同文档检索窗口也只有这段内容；条目无疾病名，标题却为 Niemann-Pick Type C1。因此没有根据标题或医疗记忆直接断言虚构。

root 按需取回普通 Git 文件 `provenance_article_25882.nxml` 后，独立阅读其 `History and Physical` 确认：真正章节题名是 **Niemann-Pick Disease**，首篇参考文献 `article-title` 才是 **Neurodevelopmental Characterization ... Type C1**。正文先分别讨论 A/B/C，随后写 `The following findings are expected during examination of the body systems.`，再列各系统的一般 NPD 表现。八条输出均限定 C1 不受该来源支持。最终改为 `distorted`，保留初判—复查记录和 Git blob `309254aa792fa719b26aaae78f1a018997fba53e`。

此例是一个完整溯源链：原书标题/参考文献层级 → 解析器错误选题名 → 缺主语的条目窗口 → 抽取器使用错误亚型题名。最早错误在 payload 构造阶段；不能全部归因于 LLM 不懂医学。

## 语义与契约符合度分开

以下忠实语义单元仍有格式/来源契约问题：O1-008、065、067、071、072、074、076。

- O1-067 的 `presents as ascites` 是从包含四症状的原句合成的引文，不是逐字子串，但 ascites 的临床关联完全可溯源。
- O1-071 的 `variable` 不在 modality 枚举，且引文插入省略号；临床影像关联仍忠实。
- O1-065 将肺动脉高压标作 symptom，O1-076 在 feature_of 上保留 comparator，属于字段契约/类型问题。
- O1-074 将描述性的“6 个月”近似为 180 天；记为日历单位近似警告，而未把这一典型病程描述当作硬性精确截止值。若后续引擎将它用作严格排除，则需要重新评价编译/执行层。

`metadata_warnings` 逐 raw_index 保存引用非逐字、枚举不合法、comparator 使用和上述特殊警告，不把它们偷偷混入“无来源幻觉”。目前本包 0 个严格虚构仅表示这 90 个输出在已审查来源范围内都有可识别祖先，**不证明整个抽取器不存在虚构**。

## 归因证据的强弱

原始缓存与输入的对照可以直接定位多数错误发生于 `payload_to_raw`，这是 B 级的错误起源证据；它不自动证明是模型容量不足。多数 relation/scope 错误的具体诱因仍只能列为 C 级：提示词没有完整的方向类型契约，schema 没有独立作用域/组效力对象，但没有对每项进行受控 prompt 消融。

A 级可直接核验的原因包括 O1-011 的题名解析错误、O1-013 的缺少评分表示，以及正确非诊断内容的任务范围来源（提示词要求 every assertion 并列出 treated_by、prognosis 等槽位）。在 O1-019、063，实际提示词的 all/required_for 约束与原始结果发生直接冲突，记录为原始抽取违反明确约束；不把其他所有 modality 膨胀都冒称违反明确提示词。

## 审核后澄清与不覆盖的修订
