# 实现缺陷审计协议

日期：2026-09-08。冻结版本：`cursor4@bbc036e8a6ec93583be915a4609fe86278ed062c`。本轮开始时已执行禁用 LFS smudge 的定向 fetch，并确认远端无新增提交。

## 审计对象与交付边界

本任务审计上一轮 11 例、四臂机械规则实验实际使用的提取—规范化—门闸—绑定—去重—组装—求值—计分—排序链，以及直接相关的可选路径与运行入口。主代码位于 `analysis/mechanism_v2/results/RAG_GUIDELINE_ORACLE_CEILING_LOCAL/`。不把该链等同于仓库中所有 APHHM-C、MOSAIC、知识图谱或生产检索路径。

交付物包括代码锚点、确定性反例、缺陷记录、历史路径适用性、已有 redesign 覆盖映射、修复分类、所需语义技术的原始文献证据及迁移验收。用户本轮请求是排查与制定方案，因此不修改生产算法，不以合成验收结果冒充临床性能提升。

## 分类不能混用

| 维度 | 取值与解释 |
|---|---|
| 缺陷性质 | 违反已经明确的接口/逻辑约束；未规定行为的规范缺口；有意的启发式或消融策略；评测约定 |
| 修复边界 | `code_only`：既有输入足以确定正确变换；`hybrid_semantic`：确定性约束能阻止部分错误，但完整恢复需要术语、来源语义或人工裁决；`design_policy`：须先确定要执行的语义/决策政策 |
| 证据 | 历史缓存/轨迹可见；真实函数的合成反例；静态代码可达风险；尚未验证的假设 |
| 历史适用性 | 冻结 B1/S7 默认链；仅可选开关；入口/运行完整性；未接入冻结链 |
| 旧设计覆盖 | 已有明确要求但未实现；已有原则但缺可执行细节；新增要求 |

“可以用代码阻止危险匹配”不等于“只靠代码已经恢复所有合法医学匹配”。拒绝全部规则也不能被解释为修复成功。每个方案须同时说明保留能力、弃权及剩余召回风险。

## 反例与计数约定

反例优先调用原始函数或入口，在独立进程/显式复位配置中运行。必要时只替换网络传输或临时输入输出目录；不调用模型，不伪造模型响应为历史结果。合成疾病名、数值和组均是软件测试数据，不是医学标准。

缺陷条目数表示工程问题清单，不是独立因果机制数、临床错误率或受影响病例数。一个病例可能穿过多个缺陷；相同代码缺陷可能产生多个表面错误。对历史 MRR 的因果判断沿用上一轮可追溯重放，不用本轮静态发现追加新的百分比归因。

## 交付门槛

1. 每项确定性缺陷可定位到冻结文件/函数，并给出反例或历史见证。
2. 说明纯代码修复与语义恢复的边界，给出验收及回归风险。
3. 不把已有设计要求再次宣称为新发现，也不把未实现要求当成已修复代码。
4. 技术方案引用原始论文、官方规范或官方代码；区分研究指标与本任务端点。
5. 所有新交付脚本可复运行，产物有源版本与文件哈希，推送至 `cursor4`。
