# 实现缺陷审计：独立证据与方法复核

冻结代码：`bbc036e8a6ec93583be915a4609fe86278ed062c`。本复核针对本轮新增的实际复现脚本、输出、缺陷分类和已有覆盖，不是再次给 11 例做临床裁决。未更改生产源文件、模型配置或既有历史重放包。

## 1. 实际复核范围与结果

已逐段阅读四个复现脚本：`reproduce_engine_defects.py`、`reproduce_identity_defects.py`、`reproduce_upstream_defects.py`、`reproduce_auxiliary_defects.py`，并与冻结机械引擎、抽取、门闸、NLI、数值解析和辅助配置/权重代码核对。独立执行了组执行 34 项见证及 44 包历史读取、身份 23 项技术检查、上游 40 项缺陷见证与 1 项正确行为控制、辅助 6 项检查；本目录 [review_checks.py](review_checks.py) 另以 37 项核对检查各族共同源文件的哈希一致性、冻结 blob/当前文件一致性、检查 ID 与计数、44 包和 L4 历史总量，并独立调用真实 `run_case` 验证一次受到争议的 NLI 调度路径。

总体上，修正下述问题后，主要机制判断有代码和适当配置下的有限反例支撑。结果证明这些故障**可被触发**，不能把通过数写成已修复 bug 数、临床错误率、独立机制数或新算法性能。原生产代码仍含被复现的行为。

## 2. 本轮审查发现并修正的一个阻断性假阳性

初稿 UP-R33 声称 `--nli` 单独启用时不会调用门闸，依据是 CLI 用 `fake_run` 观察到 `FIX_NLI=True`、`FIX_QUOTE_GATE=False`，随后把 `if FIX_QUOTE_GATE:` 写入结果。这个推理错误：冻结代码 `run_mechanical_engine.py:354` 实际是：

```python
if FIX_QUOTE_GATE or FIX_NLI:
    from gate_assertions import gate_assertions
    assertions = gate_assertions(assertions, apply_nli=FIX_NLI)
```

CLI flag 状态不能证明被替换掉的 `run_case` 内部没有执行某路径。独立检查在**不替换 run_case** 的情况下只给 `gate_assertions` 装一个无模型回调，实际观察到一次 `apply_nli=True` 的调用。因此删除该缺陷，将其保留为正确行为控制。交付验证会拒绝残留的“gate invocation remains disabled”假结论。

这也明确了所有 mock 的证据边界：替换传输可以检验 cache 状态机；替换读取器为 24 行稀疏矩阵可以检验真正的 lift `main` 如何写键；替换 `run_case` 只能检验 CLI 参数和输出命名，不能检验引擎内部门闸。密集 top-k 用轻量张量契约替身证明代码发出了越界 k 请求，不能写成已运行真实 PyTorch/encoder 并得到该异常。UP-R29 的 fake NLI logits 只验证标签映射控制流，不证明真实 provider 的预测或实际配置已出错。

## 3. 三项措辞/夹具修正

1. **msec 被 regex 取成 ms 并非错误物理量。** 两者通常指同一毫秒单位；该见证最多说明词法跨度/后缀边界未保留，不能单凭它断言数值语义错误。负号/负范围遗漏、先遇年份吞掉后续阈值等是另有实质反例的缺陷。报告已区分这些性质。
2. **身份检查不是 22 个独立错误输出加一个控制。** IDR04/IDR05 合起来证明排列依赖，其中 IDR05 单独是正确 exact 结果；IDR15 需要结合调用者不做测量身份检查才成为整体管线风险。现改为 23 项技术检查，并标出 paired mechanism components 与显式负控制。
3. **合法、非医学的夹具更能隔离实现错误。** 身份测试的 `context_type='clinical'` 不在原枚举内，改成 `criteria` 后行为保持；五词句长过滤用明确虚构疾病/marker 句替代真实疾病诊断断言。测试目的无需依赖额外医学真实性假设。

## 4. 缺陷族不是可直接相加的独立计数

| 交叉记录 | 关系 | 统计处理 |
|---|---|---|
| ENG-03 与 IDN-09 | 同一 dedupe key/首行出处/最大模态拼接的不同审阅视角 | 可保留跨引用，不视为两个独立根因 |
| ENG-04 与 IDN-10 | 同义多行/同事实多票 | 是共享问题的两个接口，不能把见证数加成患病率 |
| ENG-13 与 IDN-03 | 都涉及候选身份；前者专指完全同 label 分母/字典覆盖，后者含大小写副本/别名污染 | 相关但不是所有实例相同；case74 不能偷换为完全同 label 的历史实例 |
| ENG-18、S27 与 IDN-08 | 消费者如何解释 Unknown/阈值，与数值输入解析互相作用 | S27 交叉引用 IDN-08；解析正确仍不自动修复消费者 |
| AUX-01 与 upstream 配置/输出探针 | 同进程配置残留、非法配置类型、输出命名分别是不同入口问题 | 区分每个状态变量/路径，不把全部归为同一种缓存错误 |
| 34 组执行见证 | 包含 S03 不误合并控制、S34 合法硬动作控制和跨分项数值检查 | 34 是见证记录数，不是 34 项新 bug |
| 历史 44 包 | 11 病例 × 4 冻结实验臂 | 不是 44 独立病例，也不是新增 44 次 LLM 重抽 |

主账本可以用工程 ID 管理修复责任，但应另有重复/相邻机制映射。“工程问题条目”与“相互独立的错误原因”是不同分母。本轮没有为 11 例以外的人群估计缺陷发生率，也没有追加各 bug 的可相加 MRR 归因比例。

## 5. 历史计数和局部修复的解释边界

组/去重部分准确保留了必要限制：当前组对象由可能错误的 key 定义，不是真实临床组全集；跨 cache ID、混合 relation/context、多个成员接相同 finding 都只是结构待审标志。重复源曝光在去重后失去代表不等于一个独立临床组被破坏，source occurrence 需要和合法 shared reference 区分。

L4 的 93/87/154/188 是实际处罚事件数。某些事件同时是 soft context、negated、group member，同一原子还可能处罚多个 target；这些子集不可相加得到错误数。`differential` 中可能有有效比较，因此 soft-context L4 数不能直接命名为错反证数。病例179等已有人工作用范围审查的记录可以支持具体错误判断，其余不能只凭字段自动临床定罪。

AUX 的 5 个实际跨病例共享 lift 查询键仅证明不完整键有真实输入入口；它没有保存每次写入前的权重，因此不是 5 个已证明数值不同的覆盖，也不是 5 个实际消费/排名错误。合成两病例反例足以证明构表函数可能依赖病例顺序；真实影响量需另查生成谱系或冻结重建。

F8、grounded backfill、NL excerpts、dense top-k 等可选/相邻路径未被冒称为历史 B1/S7 四臂必经原因。`CLOSED_WORLD` 的全未知提前退出、`--discriminative-only` 死开关分别是配置语义/参数契约问题；修补它们不等于推荐更强闭世界排除政策。F10、stable tie、confirmed 排序和是否依赖 source survivor 含有设计政策，只有先明确合同才能判断什么改动应被称为修复。

## 6. 对“只改代码能否修好”的审查意见

大多数报告正确采用了分层边界：先停止已明示字段的错误重写、first-hit、成员边丢失、组/原子/L4 不同真值、非法数值和隐式状态；再研究缺失对象/范围/别名/方向如何恢复。不能把两者混成“新模型才能解决”或“换几个 if 即全部解决”。

确定性拒绝某个错误 join 会降低错配，也可能保留 unresolved；它不自动找回正确 join。强制每 finding 只投一票会同时删除合法独立 criterion；只有 root/member/witness 身份明确才能执行正确计数。已知病原体与疾病有关不等于同义，父子关系不允许任意双向迁移，测量单位相同不等于指标相同。这些限制在身份和组执行报告中均有正反例或明确残余风险。

阶段补充在本次复核中还暴露了同类方向问题：初始 `eligible_when` 若在条件 FALSE 时直接输出 NOT_ELIGIBLE，可能把“充分资格路径失败”误当成“整体不合格”。已要求作者拆为资格充分、资格必要、完整等价定义；只有源授权的完整资格定义才允许双向判定。这个问题属于本轮**设计例子修正**，不是冻结旧引擎的新历史 bug。阶段合同的独立最终审核在任务2目录另行交付。

## 7. 验证方式

运行 `python analysis/mechanism_v2/results/IMPLEMENTATION_DEFECT_AUDIT/review_checks.py`，结果保存为 [review_checks.json](review_checks.json)。它核对实际复现产物的源 hash 与关键证据限制，不修改这些结果来制造通过。后续若作者重新生成任何输入产物，应重新运行，因为输出包含其文件 hash。

本复核不认证自动医学语义、不代替正式临床审阅、不检验新模型方案有效性。其交付结论是：排除上述假阳性并保留正确分母后，本轮可以作为实施修补、建立结构/类型/动作合同和设计后续语义研究的依据；不能宣称生产算法已经修好或临床收益已经证实。
