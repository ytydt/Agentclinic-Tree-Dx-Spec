# 新旧索引的实际输入、缓存与来源差量

**v2 的冻结诊断输入不是旧输入的超集。** 修复源解析增加了部分列表、表格与标题，但 top-k 重新选择、窗口边界变化及 focus 条件共同改变了模型真正看到的材料。全 11 例的曝光从 3,842 次增加到 3,927 次（+2.21%），实际 `text[:6000]` 总字符却从 **5,700,630 降至 5,664,749（−0.63%）**。所以“指南库更全”不能直接替换成“每例模型得到了更多且包含原来全部内容的证据”。

本报告只解释输入与抽取谱系。具体断言如何经过准入、绑定、组执行、计分改变诊断排名，见同目录病例审计和确定性反事实；这里不把来源增量当作排名因果效应量。

## 1. 审计对象、对齐规则与复算

读取两份历史 `trial_retrieval_x2_{oldidx,v2idx}.json`、四份历史抽取结果、全部被引用的原始 cache，以及上一提交的 `extraction_job_manifest.jsonl`。未请求 LLM，未下载 LFS。所有任务数、cache ID、原始断言数、保存后断言数，以及嵌入覆盖，与上一轮 provenance/cohort 数字逐项断言一致。

跨索引**不使用 gid 作为身份键**：它只是索引局部坐标。相同来源与 `SHA256(text[:6000])` 定义相同实际文本窗口；相同完整 payload 还必须包含相同 focus、标题、section 和 context hint。只有相同完整 payload 才对应同 prompt 下相同 cache ID。

旧 statpearls 的 `doc_key` 为 `statpearls|`；旧输入只有 1,215/3,842 次曝光有非空文档后缀，v2 为 3,927/3,927。因此“同 source + 标题主干”的改窗链接仅是候选来源连续性，不是已证实的同文档。逐例原文账本额外核验共享段落，避免仅凭标题作结论。标题本身可能是错误选取的参考文献题名，这个边界仍然存在。

复算：

```bash
python analysis/mechanism_v2/results/V2_INDEX_DIFFERENTIAL_AUDIT/retrieval_delta.py
python analysis/mechanism_v2/results/V2_INDEX_DIFFERENTIAL_AUDIT/source_text_examples.py
python analysis/mechanism_v2/results/V2_INDEX_DIFFERENTIAL_AUDIT/source_manual_motifs.py
python analysis/mechanism_v2/results/V2_INDEX_DIFFERENTIAL_AUDIT/validate_retrieval_delta.py
```

## 3. 缓存使哪些解释成立、哪些解释不成立

两种 prompt 都有 **2,472 个全局唯一 job 跨索引复用同一个 cache，2,472 份文件 hash 全部一致**。旧侧独有 1,274 个 job，v2 侧独有 1,354 个；所有实际引用的缓存均存在，**缺失缓存为 0**。这排除了“相同 payload 在 v2 重新采样而随机变坏”作为共享部分的解释。它不排除新增 payload 的抽取错误，也不能估计同 payload 多次抽取的方差。

| prompt / 分区 | unique job | 原始断言 | 有效断言 | 无断言 job | 其中空对象 `{}` |
|---|---:|---:|---:|---:|---:|
| old / shared | 2,472 | 23,427 | 23,427 | 42 | 2 |
| old / old-only | 1,274 | 10,252 | 10,252 | 66 | 12 |
| old / v2-only | 1,354 | 12,609 | 12,609 | 29 | 11 |
| free / shared | 2,472 | 22,622 | 22,622 | 57 | 3 |
| free / old-only | 1,274 | 10,277 | 10,256 | 74 | 8 |
| free / v2-only | 1,354 | 12,569 | 12,567 | 22 | 3 |

上表去重 job，不能与按实际曝光累计的总断言直接相加。按曝光保存的断言为 old prompt **34,338→36,837**、free prompt **33,533→35,944**。输入字符略少，断言却增加约 7%：格式恢复、列表成员显式化、窗口所含疾病数量以及抽取选择均可能增加“断言密度”，而非增加等量的独立诊断信息。

空对象与 `assertions: []` 分开保留。历史代码会把部分请求/解析异常转为空对象；这不是缺失文件，也不能一概判为模型主动认为该窗无规则。cache key 未冻结完整 prompt 文本、provider 与解析版本，故本结果是对**历史冻结文件**的严格谱系重建，不是完整运行环境因果实验。

## 4. 逐段证据：真实增补、重排、移除与格式重写并存

`source_manual_motifs.json` 另将 Catatonia、PH workup、Appendicitis 和 CPVT 四组人工选定窗口连同原始抽取输出完整保存。`source_text_examples.json` 为 11 例各保存四类实例：原样保留、共享原文但改窗、新增标题来源、丢失标题来源。每个实例包含完整 case/focus、原局部 gid、文本 hash、cache ID、case 级断言区间及实际原文段落。新增/丢失实例还逐字检查该段是否出现在另一索引本例的任一 served window。它是可复查例证集，不是临床充分性的概率样本；exact paragraph 差异可能只是断行或排版变化。

人工查阅这些对照后，至少应分清下列机制：

| 病例/焦点 | 原窗口 → v2 窗口 | 原文实际变化 | 不能混淆的结论 |
|---|---|---|---|
| DA522 / Catatonia | 480632 → 496392（病例审计）；完整逐段例见账本 | 旧窗有 3-of-12 提示却无完整 DSM 列表，v2 恢复列表；旧 Walter 亚型特征也曾被作为组 | 补齐 12 项不保证被编译成完整 3-of-12；旧较短/错误组可能更容易“满足” |
| DA773 / PH | 628614 → 661576，仅剩 Tricuspid Regurgitation focus | “无左心病需进一步检查”的原句仍存在；新窗增添 4 项右心功能参数，PH focus 不再看到该段 | 旧 PH 假排除消失兼有焦点曝光变化与改窗抽取变化；不是源端删除了该句 |
| DA119 / Porokeratosis | 610773 → 641776 | 2,445→1,580 字符，加入包括 EPPP 的 12 个常见/罕见亚型列表，替换部分一般临床说明 | 更具体实体可以首次变得可达，但仅“列出亚型名称”不等于 EPPP 的决定性判据 |
| MCR257 / Abscess | 262631 → 264498 | 非结核分枝杆菌检测表由 tab 压平转成多行，包含 M. abscessus、M. bolletii 等 | 这不是 collar-button abscess 诊断标准；词形近似触发的来源噪声可被更好排版放大 |
| MCR326 / Brucellosis | 481367 → 497194 | 1,307→1,764 字符，加入 12 项鉴别疾病列表，替换并发症/管理段 | 列表提供竞争者名称，不能自动转成每个竞争者的患者证据或刚性排除 |
| MCR475 / Neuralgic Amyotrophy | 463851 → 477657 | 加入长段 axillary nerve 解剖，删除“前脱位/强迫外展常致腋神经损伤”段 | 已有神经症状不等于源支持特定病因；窗口替换可提高解剖近邻的词面重合 |

### DA773 的可溯源负对照

旧 free 的 case-level assertion **1871** 把“没有左心病证据则需要继续检查”变成 `Pulmonary Hypertension / evidence of left heart disease / excludes / negated`；1872 又将存在左心病写为 PH 的反证。两者来自 old focus `Pulmonary Hypertension`、gid 628614、cache `126e8b394f9088cbe176dbf4607244f410ef7d79`。源语义是检查路径，不是疾病排除。

v2 的 gid 661576 仍逐字含有这一整段，但在本例只对 `Tricuspid Regurgitation` 曝光，并追加 Fractional area change、组织 Doppler、TAPSE、RV myocardial-performance index 四项。新 free cache `43e95454cc794e5e892b96929b980566df5b23ee`（case rows 2148–2159）没有这些 `excludes/argues_against` 输出。旧同 Tricuspid Regurgitation 焦点 cache `35863f2be44982434e86daf90de99eccfb5b185c` 却有 row 2037 的错误排除。这组对照支持两条独立事实：

1. PH 焦点失去该段，足以阻断该焦点下旧错误的再抽取；
2. 同为 Tricuspid Regurgitation + free prompt，扩窗后的输出也改变了。

第二条仍不是“扩窗自动改正关系”的可推广因果估计，因为上下文变了且每个 payload 只有一次冻结抽取；它是有定位证据的输出差量。排名影响由病例回放另行确认。

## 5. v2 还遇到偏向旧文本的 join 字典

实际 `join_embeddings.npz` 含 **14,013 个字符串**，与当前 `build_join_embeddings.collect()` 从以下三份 legacy k30 文件采集的字符串集合**完全相同，对称差为 0**：`trial_extraction_k30clean.json`、`trial_extraction_k30oracleclean.json`、`trial_extraction_k30oracleclean_groups.json`。四个 x2 抽取臂均未在该字典生成器输入列表中。

`embed_sim(a,b)` 任一字符串不在冻结字典就返回 0；这直接改变语义匹配的可达性。四臂所有 560 个 finding 侧字符串均有嵌入，但新表达的 predicate 没有同样待遇。

| 抽取臂 | 唯一谓词覆盖 | 按断言行覆盖 |
|---|---:|---:|
| old prompt / old index | 9,191/15,437 = 59.54% | 25,839/34,338 = 75.25% |
| free prompt / old index | 7,684/15,322 = 50.15% | 23,237/33,533 = 69.30% |
| old prompt / v2 | 8,348/16,584 = 50.34% | 24,983/36,837 = 67.82% |
| free prompt / v2 | 7,175/16,396 = 43.76% | 22,778/35,944 = 63.37% |

此差异主要发生在改变的输入上，而非原样复用部分。例如同标题同 focus 改窗的 old prompt 断言，覆盖从旧 **5,831/7,673（76.0%）** 降到 v2 **5,024/8,821（57.0%）**；free 对应 **5,367/7,732（69.4%）→4,798/8,644（55.5%）**。原样 payload 部分两索引的断言与覆盖完全相等。

这是**比较条件未统一**的确定证据；它既可能阻止正确语义桥接，也可能阻止错误近似匹配，不能仅凭覆盖降低宣称其净 MRR 效应为负。需要固定四臂联合字符串字典，或分别关闭 embedding，做配对回放；后者同时删除正确与错误 join，不能视为等价的最终修复。

## 6. 本分项达到与未达到的归因边界

可以确定：源解析补全之后，进入抽取器的材料混合了真正新增内容、旧内容格式恢复、相邻段替换、focus 变化、来源预算重分配；64.0% 的 v2 实际曝光原样复用历史抽取。新输出增加了断言质量不明的密度，且语义 join 的可用词表偏向更早输出。这个输入链本身已经否定“只改变指南完整性、其他条件相同”的解释。

不能从本分项单独确定：这些因素分别贡献了多少 MRR，某条新文字临床上是否应命中本例，或者更多原子行是否包含更多独立诊断信息。病例中如果决定性数值/限定已经同时存在于源和 finding，而执行层只读 label/canonical 或错误合并对象，应归到下游而不是检索。当前旧/新只是两份冻结观测；差量定位与针对性回放结合才能支持局部机制，不能把多个相关变化无条件加总成全 11 例唯一解释。
