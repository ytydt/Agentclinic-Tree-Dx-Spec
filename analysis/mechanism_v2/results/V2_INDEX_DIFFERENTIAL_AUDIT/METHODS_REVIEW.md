# 差量审计的方法独立复核

复核日期：2026-09-05。基线 `cursor4@6fa8fd7aa2548cc01ac81f2d5261801190244d27`。本文件由独立 AI 方法审阅员撰写，未修改生产程序、其他审计员的判定或实验结果。审阅对象包括冻结协议、任务原始金标与候选、端点复算、曝光差量、回放仪器代码和已经保存的回放包；**不是临床专家裁定，也不是重新开展的盲法临床准确率评估**。最后报告尚在形成，以下结论区分已核查与交付前条件。

## 1. 判断：此前证据能够解释失败链，但尚不足以解释全部差量

前两次审计已经证明抽取不忠实和执行错误实际存在，并通过例74的局部干预识别一条决定性错误否决。其能力边界样本只在 v2 下比较旧/新提示词，不能估计旧索引下来源规则的忠实率，也不能自动把 v2 性能回退归因于“语义错误数量增加”。新差量审计必须补足来源替换、旧错误带来的偶然优势、非致命评分累积及候选间交互；当前协议和完整贡献回放适合完成这一任务。

旧/旧到旧/v2的代理 MRR 差为 −0.060606；其中例74的名次算术项为 −0.068182，其他十例合计 **+0.007576**。free/旧到free/v2的代理 MRR 差为 −0.106061；例74仍为 −0.068182，其他十例合计 **−0.037879**。因此同一“v2回退”在两提示词下的剩余构成不同。以上是按病例可加的指标算术，**不是可加的错误因果贡献**；同例多个错误对名次的影响一般不可相加。

## 2. 端点和四臂必须保持的边界

| 项目 | 复核结论 | 报告必须使用的口径 |
|---|---|---|
| 四臂名称 | 端点脚本用 `new_old/new_v2`，回放和来源脚本用 `free_old/free_v2`，位置对应一致 | 明示两套别名；new/free是历史提示词臂，不能暗示新调用或只改索引 |
| 索引效应对比 | `old_old→old_v2`、`free_old→free_v2`保持名义提示词轴 | `old_old→free_v2`混合两轴，单独列为合并变化；缓存未冻结完整provider/prompt-body代次 |
| 原始任务 | 端点中的gold与legacy标签直接来自 `trial_tasks_11_all4.json` | 可复算，仍是人工筛出的11例开发集，不能外推800例临床收益 |
| explicit complete标签 | 映射列出的标签确实出现在任务候选内，父类/组件没有被偷换成完整标签 | 这是保守的已生成标签范围审计；未穷尽临床语境下安全同义项，不能称“纠正后的clinical-complete准确率” |
| 缺失完整标签 | 522、773、119、257、91、179不提供所需完整标签 | 候选缺失与排序失败分开；两个组件分别进入top-k不等于关系组合诊断进入top-k |
| 有证据标签 | 当前条件 `n_assertions>0`只证明绑定了来源断言 | 建议改称“有绑定断言”，并另报 `n_joined>0`及有非零贡献；三者不等价 |
| 排序规则 | 实际为 `(bool(eliminated), -len(confirmed), -score)`，之后保留候选原顺序打破完全平局 | 每次名次变动必须报告硬否决、确认数、分数和同分顺序；单纯比总分不足以解释排名 |
| 例74重复候选 | 当前冻结B1/S7默认来源回放两v2臂有绑定断言的CPVT均第10，空重复标签第4 | 前报告叙述中的“第10/13”与其表格/冻结trace不一致，不能沿用13而不给具体配置来源 |

旧提示词/旧索引的七个legacy top-3，准确的拆法如下：

| 病例 | 排名标签 | 范围判断 |
|---|---|---|
| 326 | Brucellosis | 完整已生成疾病标签 |
| 475 | Neuralgic Amyotrophy | 完整已生成疾病同义标签 |
| 49 | Appendiceal stump appendicitis | 完整已生成疾病标签 |
| 74 | Catecholaminergic Polymorphic Ventricular Tachycardia | 完整已生成疾病标签，但已有错误证据和绑定问题 |

因此可以说“七项中四项具有完整候选标签、三项只命中父类/组件”，**不能改写为‘四例临床正确+三例错误’**。完整名称是否由合法来源和患者证据推出，仍是另一层审计终点。旧top-3是候选名次结果，不能证明旧抽取忠实、规则充分或临床推理正确。

## 3. ‘更全的库’不等于‘更多上下文的严格超集’

曝光差量脚本按相同病例、source+text及完整payload比对，未使用跨索引gid作稳定身份，这是正确设计。现存记录显示：旧/v2曝光次数3842→3927，唯一输入payload3746→3826；但实际输入字符为 **5,700,630→5,664,749**，略有减少。2513次曝光payload一致；其余含改窗口、换来源/条目、移至其他focus和丢失旧曝光。数据库修复了源内容遗漏，而病例实际输入同时发生了替换；不能把这批历史四臂当成“只增加完整指南规则”的单因素实验。

同一提示词两索引共享2472个唯一缓存job，输出文件逐字节相同。该子集有助于定位**下游差量**：相同抽取行仍可能因输入顺序、来源元数据、去重代表、组拼接、claimants或竞争者状态而改变作用。它不能估计模型对同输入的稳定性，因为是复用同一个缓存，不是独立抽取。

`source+title-family`只能作为找可能对应原文的检索提示。老StatPearls缺document ID且标题已存在首条参考文献污染；同名书籍也可能包含多个疾病。因此：

- `same_title_family...changed_window`不应重命名为“同文档新增/删除规则”，除非人工核实正文或原始文档身份。
- 跨索引gid不是稳定身份；同一gid更不能作为干预行的定位方式。
- 句子截取变化、列表开头或计数域不完整应保留为来源输入变化；不应把全部变化归给LLM随机失真。
- 同窗重新分组还会改变缓存输出数量，未必表示医学规则新增；原子行数不能直接代替独立规则数。

## 4. 干预究竟测量什么

回放器保留原始合并断言行号、去重support行号、各stage及全部贡献，并核对仪器化结果与历史截断结果一致；这些设计可以支持逐条追踪。下表是解释干预时必须使用的区别。

| 干预 | 实际作用位置与传播 | 可解释的终点 | 不能宣称 |
|---|---|---|---|
| `delete_raw_ids` | F7前删除；可能改变门闸、去重代表、组成员数、singleton退化、join、claimants、硬状态、L4 | 该删除操作在冻结管线中的总局部反事实 | 被删断言自身的纯直接分数；完整临床修复收益 |
| `patch_raw` | F7前改字段；F7可能再改写；关系变化可改变去重键及组归属 | 特定编译输入补丁在现有管线的效应 | 仅修改了一个语义槽且其他执行状态不变；补丁等于参照标准 |
| `block_joins` | 最佳匹配选定之后、claimants之前阻断，无fallback | 移除该连接后连带传播的总效应 | 生产matcher重排后的结果；固定其他候选权重的直接边效应 |
| `remove_contributions` | 评分后、L4前移除数值；硬否决和确认状态保留 | 固定既有状态/claimants的数值贡献敏感性 | 消除了一条错误否决或错误确诊；真实修复后的排名 |
| `block_layer4` | 跳过被选中来源候选断言的比较循环 | 经实际penalty差量验证的比较扣分效应 | applied日志条数等于被取消罚分数 |
| 全部关闭embedding | 所有臂只能走剩余匹配通道 | 冻结非embedding条件下索引差量是否仍存在 | 补齐所有缺失embedding后的结果，或缺失向量净伤害大小 |
| 同fact合并/所有组删除 | 改变计票、信息组织、真规则和假规则同时受影响 | 聚合敏感性或上下界探针 | 只删除了错误或已经实现有效抽取器 |

尤其 `block_joins`会删除该候选对fact的claimant，进而提高其他候选相同fact的IDF权重；若某错误join促成确认/否决，它还会改变生存集合和L4。因此“去掉一条对目标有利的错误证据反而目标名次提高”并不悖论，应先检查这些传播。删除一个重复support行也可能没有任何影响，因为另一行仍为代表；删除原代表可能暴露新的阈值、modality、组ID或来源。

`_block_layer4`的hook在检查comparator、关系和患者present状态之前执行，`applied_interventions`记录的是选中bound row。最终报告应使用实际 `layer4_penalties`前后差量统计阻断效果，或将日志措辞收窄为“row skipped”；不能将无方向比较的行也算为成功取消罚分。每个手工selector应核验原始行身份、命中的代表/support及零命中情况，保留有意的no-op作对照。

## 5. 新发现的组身份传播风险

生产组键为 `(_title, _section, _focus, local_group_id, normalized_subject)`，未包含缓存job或源窗口身份。结构筛查已读到多例**同一个执行组由多个cache的代表行构成**；例522 free/v2的Catatonia含三个这样的组，成员数6、11、5，而free/旧有一个10成员组。其他病例亦有同书名/同section的本地g1跨窗并合。

跨cache本身不证明错误：真实同一判据可能确实跨页/跨窗；但每个LLM输出局部编号g1不是全局组身份。必须回到来源确认：原本是不是同一标准、共享成员是否被去重从另一组夺走、首成员的logic/n是否覆盖其余成员、两个表面不同的成员是否只命中同一患者fact。不能以“成员变多”当作判据组更完整，也不能以“有一个组对象”当作嵌套语义保存成功。

具体病例语义由负责该病例的审计员判定；本复核的[结构账本](methods_review_checks.json)只把跨cache情况作为定位信号，不统计为错误率，也不独立宣称其rank效应。

## 6. 防止过滤器靠金标制造收益的反例要求

逐例审计使用金标帮助定位错误可以接受，但由此得到的是oracle机制探针。规则是否错误应由原文和患者事实决定，不能以“支持干扰项”作为错误判据。以下反例需要进入报告或下一阶段验收：

1. **原文完全正确，患者join错误。** 只阻断错误连接，保留原始规则；例如另一器官出血或儿童自然病程不能凭词面匹配当作本病例事实。把源规则删掉会误教抽取器。
2. **原文弱证据正确而诊断不完整。** Catatonia、PFO、Porokeratosis的正确组件证据不能因为不是完整金标而删除；需要的是输出粒度/关系判据和独立终点。
3. **部分正确组不等于全组正确。** 来源有多数/至少k/时间前提时，保留几项正确feature仍是破坏整规则；但作为弱证据的用处与刚性criteria忠实率分开计量。
4. **有源治疗/检查行与模型幻觉不同。** 当历史prompt允许treated_by，忠实的治疗事实不是无源幻觉；诊断引擎把它当患者支持才是任务准入/执行问题。
5. **消错让legacy分数下降。** 旧索引靠错join推高父类/组件、给真正完整候选错误确认，移除后top-3可能变差；不能因此拒绝语义修复，也不能把这种下降叫临床能力下降。
6. **局部修复与全局筛除相反。** 例74仅删除错误CPVT否决与全局删除excludes/argues_against的排名不同，后者还解除竞争诊断约束；这已经是范围过滤反例，不能继续用全局收益代替局部原因。
7. **缺失不是阴性。** 为了让组执行得出金标，不能补造病例未提供的致病变异、运动诱发特征、全部排除检查或正常器官结构；本轮能反驳一个否决不等于能刚性确诊。
8. **可靠但多次重复的证据。** 去重/同fact合并应对真规则和假规则使用同一机制；不能仅合并竞争者而保留目标重复投票。

## 7. 交付前验收意见

以下条件满足后，可以将任务一表述为“对这11例历史缓存的完整运行差量和若干局部错误因果路径已有充分解释”；仍不能称确定了更完整指南库的总体因果负效应。

- 四臂44个回放均与既有B1/S7输出逐字段一致，全部候选分数由未截断贡献和L4精确重构；生产代码和输入文件SHA固定。
- 每例至少保留完整候选或明确父类/组件目标及主要竞争者；解释从来源到执行的首次损坏和后续传播，而非只列rank。
- 旧top-3七项逐项区分合法证据、错误增益、错误扣分、被误杀竞争者及候选缺失；合法且有用的弱证据不被笼统归为噪声。
- 例74之外的名次退化和看似改善都有定位/干预；没有rank变化的病例也检查score margin、确认状态或未来小扰动可暴露的脆弱性。
- 干预记录实际命中，明确raw-delete、join-block和numeric-only三类效应；给出顺序依赖和不可加的例子，不进行未识别的百分比因果分摊。
- embedding关闭实验只作为可用性控制；若未补齐embedding，则保留“全覆盖后的净影响未识别”。source lookup对照沿用前轮已确认所有rank不变的结果，勿把已证实但零rank效应的F7来源缺陷当成这11例回退主因。
- 主报告显式承认：相同缓存复用、prompt/provider代次不完整、端点有范围污染、候选集已固定、样本经开发选择。能力边界审计的v2来源分母与本轮全链差量不是同一estimand。

本复核建议是完善归因口径和验收条件，不要求为了‘更严格’任意新增临床事实、重新调用模型或修改生产算法。
