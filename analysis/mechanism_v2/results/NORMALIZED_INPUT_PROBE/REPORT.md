## 0. 结论

**四条集群否证在规范化输入下仍然成立。理由是覆盖面：规范化只作用于化验与部分生命
体征，对承载鉴别性叙述的 history / imaging / pathology 的命中率是 0.0000。**

前提本身是对的——此前所有集群实验的生成器确实直读原始题干，`VignetteParser` +
`FindingNormalizer` 这条通路从未被拼进去。我此前 Q10 只用它去**事后接地已抽好的
fact**，没有把它当作**输入表示**来测。这次测了。

规范化确实按预期工作（`Potassium: 6.2 mEq/L → Hyperkalemia (H)`），但触及面很窄：

| 量 | 值 |
|---|---:|
| evidence item 拿到规范名称（200 例 / 3561 条） | **0.0595** |
| 其中"解析出数字但映射不到表型"（不计入上行） | 169 条 |
| fact ledger 上拿到规范名称（2308 条） | **0.0542** |
| `laboratory` modality 命中率 | 0.2658 |
| `history` / `imaging` / `pathology` 命中率 | **0.0000 / 0.0000 / 0.0000** |
| 每例复合串拆分带来的原子增益 | **0.03** |
| 每例同义归一合并次数 | **0.06** |

同时保留一件确实新增的东西（**不是**集群机制）：96 条正常值被转成显式排除项。

### 0.1 一处口径修正

首轮我把 `normalize_multi` 返回非空就算作"已规范化"，得到 0.1070 的产出率，并据此
写下"命中率与特异性反相关"。**这一条是错的**：381 条非空里有 169 条只解析出了数字、
映射不到表型（如无参考区间的 CA-125），而这些恰好集中在低特异 fact 上，制造了假的
单调性。收紧为"至少一条结果带 `hpo_term`"后，特异性三档为 medium 0.0806 >
high 0.0467 > low 0.0302，**非单调，反相关不成立**。本报告全部数字使用收紧口径。

## 2. 为什么否证没有被推翻

`CLUSTER_SIGNAL_ANATOMY` 把死因定位得很具体：集群信号在病例内决定性比较上
**42.73% 无法表态**，分辨率不足。所以要问的不是"规范化是否更干净"，而是
**它能不能提高观察分组的分辨率**。规范化有三条可能做到这件事的机制，逐条实测：

| 机制 | 预期效应 | 实测（200 例） |
|---|---|---:|
| **拆复合串** → 观察粒度变细 | 直接降低平局率 | 仅 **5** 条被拆，每例原子增益 **0.03** |
| **同义归一** → 同一观察的不同表面形式合并 | 分组身份更干净 | 每例合并 **0.06** 次 |
| **方向/否定** → 正常值变显式排除 | 新增判别信号 | **96** 条（唯一真实增量） |

前两条约等于零。要修的是 0.4273 的平局质量，而能改写成规范名称的证据只占 5.95%，
且改写后几乎不产生新的分组边界——**这个量级不可能重新分配那 43% 的平局质量。**

### 2.1 一条我必须自己反驳的假设

"产出率低"单独不足以定案：化验类 finding 可能恰恰是最有鉴别力的那一类，5.95% 的
证据仍可能承载大部分权重。这一条必须在集群信号**实际被计算的那个数据结构**上测，
所以把规范化器直接跑在 multistance 冻结 fact ledger 的 `raw_span` 上（2308 条）。

结论是：**规范化的覆盖面沿 modality 切得极干净，而它切掉的正是鉴别性叙述。**

| modality | fact 数 | 规范化率 |
|---|---:|---:|
| laboratory | 380 | **0.2658** |
| exam | 541 | 0.0425 |
| treatment_response | 59 | 0.0169 |
| history | 682 | **0.0000** |
| imaging | 504 | **0.0000** |
| pathology | 139 | **0.0000** |
| genetics | 3 | 0.0000 |

`history`（682 条）、`imaging`（504 条）、`pathology`（139 条）合计 1325 条、占 57.4%，
命中数为 **0**。这三类是 MCR 里承载鉴别力的部分——病理描述、影像形态、病程叙述都不是
数值型，`loinc2hpo` 结构上不覆盖。这与 `SYMPTOM_CLUSTER_READINESS` §9.3 的"54.4% 的
span 根本不能用 HPO"是同一条硬约束，此处以更严口径复现。

支撑侧的检验：在 1711 个被判定的候选上，**完整**候选的可规范化支撑占比 0.0700，
**不完整** 0.0543，差 **+0.0157**。符号为正但量级极小，且完整档只有 **80** 个候选、
基准率本身仅 5–7%，**不足以支撑任何结论**；把它读成"规范化证据更重要"是过度解读。

## 3. 这次没有测什么

必须说清边界，否则容易把上界论证读成实测：

- **没有在体重跑 G1 生成。** 把结构化 JSON + 规范化名称真正喂给生成器、再看保留率，
  这件事需要在线调用，没做。第 2 节是**上界论证**：规范化改写的内容只占 5.95%
  且几乎不改变分组边界，所以生成器看到的**内容**变化很小。这不等于在体实测。
- **上界论证只覆盖"规范化"这一半，不覆盖"解析"那一半。** 见第 4 节——解析步骤对
  输入的改动其实很大，那部分我没有否证。
- **只在 MCR 上做。** 集群线按方案 §0 本就是 MCR-only。DA 侧另有一个障碍：
  `vignette_parser.txt` 会抽取 `options`，直接用在 DA 上构成选项泄露，需先做非泄露变体。
- **临床端点仍是三模型面板敏感性**，不是人工根真值。

## 4. 两条真实存在但不属于集群的方向

审计过程中冒出两件与"症状集群"无关、却确实未被否证的事。不合并进集群叙事，单独记账。

> **两条已于 2026-08-24 各自零调用判过门，均 NO-GO，本节两笔账已结。**
> 见 [`../INPUT_CHANNEL_GATES/REPORT.md`](../INPUT_CHANNEL_GATES/REPORT.md)。
> §4.1 的否证是**需求不存在**：生成器只有 2.93% 的 `support_spans` 越过 C1 ledger，
> 且解析器的 gold 词汇回收优势在天花板病例上只有 +0.0113、在已达成病例上 +0.0549——
> 优势集中在不需要它的地方。**注意被否证的是"C1 的压缩在饿着生成器"，
> 不是"解析器抽得更完整"这一事实（0.8354 vs 0.6095 仍成立）。**
> §4.2 的否证是**触及面不够**：可翻转的 25 例上未被引用的排除项仅 0.28 条/例，
> 而既有 contradict 通道已被喂饱（327 条 absent fact、58.41% 被引）且不判别
> （0.65 vs 0.6427）。唯一留档观察是 11 条正常值在同一病例内被同时用作支撑与反驳。

### 4.1 抽取完整度：解析器比 C1 fact ledger 多拿 22.6pp

同 100 例、同题干上配对比较：

| | 条/例 | 题干 token 召回 |
|---|---:|---:|
| `VignetteParser` | 18.28 | **0.8354** |
| C1 fact ledger（multistance 在用） | 11.67 | 0.6095 |

这是输入表示上的**实质差异**，而且它来自解析而非规范化，所以第 2 节的上界论证管不到它。

但不能直接读成"C1 在丢有用信息"：两者设计目的不同。C1 是带 modality / specificity /
polarity 标注的**判别性压缩**，主动丢弃噪声；解析器追求**完整**（v2 冻结的 checklist
recall 为 1.0、0 幻觉嫌疑）。token 召回高也部分来自它照抄人口学与虚词密集的措辞。
**孰优需要单独预注册的实验，本报告不作判断。**

### 4.2 阴性证据通道：96 条显式排除项

规范化把正常值转成 `negated_hpo_terms`（loinc2hpo 的 N 档），当前流水线只把它们
当作未标注文本。这是**阴性证据 / 排除**机制，不是集群宽度机制，两者不应互相顶替。
量级偏小（200 例 96 条），入场前应先有零调用判据。
