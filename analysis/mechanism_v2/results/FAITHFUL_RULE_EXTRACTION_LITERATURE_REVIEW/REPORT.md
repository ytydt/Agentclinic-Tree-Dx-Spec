# 从指南文本到忠实可执行规则：方法、保证边界与可迁移证据

检索与核验：2026-09-05 至 2026-09-06。仓库参照 `cursor4@6fa8fd7aa2548cc01ac81f2d5261801190244d27`。这是第二任务的独立交付；第一任务见 [新旧索引差量审计](../V2_INDEX_DIFFERENTIAL_AUDIT/REPORT.md)，第三任务见 [改进方案](../RULE_EXTRACTION_EXECUTION_REDESIGN/REPORT.md)。

## 1. 直接回答

**现有研究可以明确表达和执行嵌套的连词、量词、否定与作用域，也提供减少误译的有效部件；本轮纳入的研究没有证明能够从任意临床指南自动、零错误地恢复这些语义。** 更成熟的系统通常将人工知识工程、受控表达、确定性编译和独立验证结合。许多 LLM 方法主要改善可执行率或最后一个答案，尚未测出完整源规则的忠实提取能力。[ACE 解释规则](https://attempto.ifi.uzh.ch/site/docs/ace_interpretationrules.html)、[CLOVER](https://arxiv.org/html/2410.08047v2)、[HL7 CPG 方法](https://hl7.org/fhir/uv/cpg/methodology.html)。

本仓最值得借鉴的不是某种输出格式，而是以下组合：**先建立有原文锚点的规则、概念与逻辑依赖，再用受约束的编译检查结构；针对易混读法生成反模型；把患者事实和推断权限独立审查；最终按完整规则执行一次。** 这是一项由审计和文献支持的设计推论，尚未证明在本仓提高性能。

六个会改变方法选择的发现：

1. **CPGPrompt 并未解决任意递归规则抽取。** 全部生成树经过人工验证，测试病例又从这些树生成；官方节点仍是字符串条件列表加阈值，并禁止条件成员嵌套。它的执行器先汇总成员再走组动作，值得借鉴；其无 unknown 的二元判读和顺序合并不能直接照搬。[论文 §2](https://arxiv.org/html/2601.03475v1)、[冻结实现](https://github.com/bionlplab/CPGPrompt/tree/aa6061e2f6b2e810f7c5897232f45ab223a956a2)。
2. **一个叫“逻辑等价”的指标也可能忽略量词。** LogicLLaMA 官方实现的布尔向量路径没有解释量词前缀。因此 LE=0.924 不是92.4%的完整规则忠实率。[论文](https://aclanthology.org/2024.acl-long.375/)、[解析实现](https://github.com/gblackout/LogicLLaMA/blob/785a2c08e8fe964c8b2a10bb183ce5a08867aa3b/fol_parser.py)。
3. **原子成绩不能替代完整组成绩。** Text2MDT 的最佳完整树精确匹配率为0.490（100例测试、5次运行均值），0.748属于树组装子任务。两者测量对象不同。[Text2MDT §6](https://arxiv.org/html/2401.02034v1#S6)。
4. **单结论正确会掩盖整包形式化的错误。** FoVer 的单查询结果为95.5%，扩展评测中要求每样本全部查询正确的严格口径为78.5%；两者不能当作同一缓存上只改判分的纯因果差值。这仍是行为终点，不是原文逐槽位忠实度。[FoVer §5.1](https://aclanthology.org/2025.tacl-1.61.pdf)。
5. **扩大翻译覆盖与提高正确率不是同一目标。** NICE→ASP 的临床审核直接观察未译、正确、错误、关键遗漏和新增内容。但当前官方 CSV 的分母是生成规则行加未译占位，部分值又与论文图不同，不能当作固定源规则上的忠实召回率。[论文](https://arxiv.org/pdf/2608.30022)、[逐表复核](clinical_llm_review.md)。
6. **成熟标准也可能在误用时重现组错误。** CQL 的 `AllTrue` 忽略 null；空列表、全 null 列表及 null 列表均返回真；OWL 的开放世界与 SHACL 的数据合规检查又有不同语义。需要明确数据完备性和决策授权，不能只换后端。[CQL 参考](https://cql.hl7.org/09-b-cqlreference.html)、[OWL 2](https://www.w3.org/TR/owl2-primer/)、[SHACL](https://www.w3.org/TR/shacl/)。

## 3. 需要先把“准确”分成六种对象

| 对象 | 可检验命题 | 通过后仍可能怎样出错 |
|---|---|---|
| 语法 | AST可解析、括号和字段合法 | AND换成OR仍合法 |
| 静态语义 | 类型、元数、绑定、作用域合法 | 同类型的mPAP/PASP、血/组织指标错配 |
| 参考等价 | 固定符号映射及背景理论下，两公式不存在区分模型 | 参考公式或符号映射本身误读原文 |
| 推导 | 结论确实由输入理论推出 | 输入理论已经漏掉限定、增添常识或颠倒必要性 |
| 源文忠实 | 独立规则、组完整性、每个语义槽位及出处正确 | 患者观测和规则要求仍未正确对应 |
| 临床任务 | 完整诊断/决策与病例相符 | 部分正确标签、错误抵消或评测器宽松造成假成功 |

这个分层是本次综合，不是文献已有统一等级。PICARD、Synchromesh与类型约束主要加强前两层；FOL证明器加强第四层；CLOVER、受控语言和有人工参考的等价检查帮助连接第三与第五层。第五层仍须对源文及候选解释作独立裁决。[PICARD](https://aclanthology.org/2021.emnlp-main.779/)、[Synchromesh](https://arxiv.org/pdf/2201.11227)、[CLOVER](https://arxiv.org/html/2410.08047v2)。

对本仓而言，不能再用“有多少抽取行”“solver能跑”“11例MRR多少”代替源规则能力边界。任务一已经表明：无直接贡献的行也会改变 claimants；部分金标可能根本没有完整候选；一个错误修复可能揭开此前被另一个错误压住的干扰者。单个正确终点对全包知识的质量约束非常弱。

## 4. 忠实组合抽取的几条技术路线

### 4.1 先规定解释，再编译：受控语言与人工知识工程

ACE/DRS 给可接受输入明确的连词、量词和照应解释；HL7 CPG 先建立领域伪代码、概念和流程再形式化。两者共同把隐含约定变成可审查对象。[ACE](https://attempto.ifi.uzh.ch/site/docs/ace_interpretationrules.html)、[HL7 CPG](https://hl7.org/fhir/uv/cpg/methodology.html)。

迁移关键在**自由指南→受控释义**这一段。可以让模型产出“条件作用于何人/何时/何项决策”的中间表示，但必须同时显示原句和差异。把原文必要条件改写为充分条件以后，再用完美解析器翻译，得到的仍是错误公式。人类审计的责任不能因有编译器而消失。

### 4.2 先识别逻辑依赖，再组合：MRS与CLOVER

MRS用handles、变量及限制域/主体保存范围，并允许尚未确定的作用域；CLOVER在LLM框架中分离语言原子和连接结构，再组合公式、产生反解释。[MRS](https://www.cl.cam.ac.uk/~aac10/papers/mrs.pdf)、[CLOVER](https://arxiv.org/html/2410.08047v2)。

对本仓最重要的推论是：**平面序列化不一定有错，消除了组身份、绑定、范围和根结论才有错。** AST、带明确子式节点的图、DRS或程序都可以保存结构。正确表示还需处理跨页表、例外脚注、局部组ID和共享叶子；文献算法不会自动补回没有送入上下文的成员。

源文存在多种合理读法时，可保留多个带证据的结构。多数投票选中一个合法公式不构成语义证明；所有样本也可能共享同一误读。保留歧义及拒绝过强动作比暗中选默认 `any` 更诚实，但要测由此付出的覆盖损失。

### 4.3 受约束生成：把结构错误在生成/编译时挡住

PICARD实际检查SQL别名与作用域；Synchromesh通过completion engine限制语法/类型/上下文；类型约束生成进一步判断前缀能否完成为所需类型。这些超出了仅检查JSON的能力，但可完成前缀不保证模型在预算内实际完成输出。[PICARD](https://aclanthology.org/2021.emnlp-main.779/)、[Synchromesh](https://arxiv.org/pdf/2201.11227)、[PLDI类型约束](https://arxiv.org/pdf/2504.09246)。

但“槽位合法”与“槽位正确”仍不同。可以禁止游离变量、未声明组域、量纲冲突及缺阈值的计数；不能仅凭类型确定“需要排除其他原因”究竟控制诊断还是工作流。模型应该在允许的语义类型中选择，编译器不应替它猜测源文省略内容。

### 4.4 等价、反模型与修复：检验具体差别，保留独立参照

若有可信参考公式，可检验 `¬(φ↔ψ)` 是否可满足；反模型展示两个公式在哪个输入世界行为不同。CLOVER将反解释交给模型判断源文，Logic-LM++在修复时恢复源文并允许回退。Sketch的反例循环则以独立形式规格为参照。[CLOVER](https://arxiv.org/html/2410.08047v2)、[Logic-LM++](https://aclanthology.org/2024.nlrse-1.6.pdf)、[Sketch](https://people.csail.mit.edu/asolar/papers/asplos06-final.pdf)。

这可用于区分“每人有某项”与“存在同一项适于所有人”、`A∧(B∨C)`与`(A∧B)∨C`、充分条件与必要条件。**求解器只能证明形式差别；它不能判断哪个公式才是作者原意。** 同一模型生成规格、程序和测试可能形成自洽误读。因此修复实验需分别统计修对、修坏、未改变及错误类型迁移；不能只记录执行成功率。

### 4.5 谓词和符号身份：组合正确以前必须先指对对象

给定金标谓词与自动预测谓词的实验揭示了身份识别本身的巨大成本；MenTaL跨句维护概念—符号对应，针对同义改写造成的漂移。[谓词条件研究](https://arxiv.org/html/2509.22338v2)、[MenTaL](https://arxiv.org/html/2506.04575v3)。

本仓需要同时防止**过分拆分与过度合并**：PECAM-1/CD31的别名桥接要保留，Hemangioma/Angiosarcoma、Carcinoma/Sarcomatoid SCC、mPAP/PASP则不能因为字符串相近而相同。91的独立复审正说明“未见字面”也不能直接推断概念没有到达。符号一致性指标若只罚拆分、不罚合并，会奖励另一个方向的错误。

### 4.6 临床树、图、Python和skills：表示载体不能代替语义合同

Text2MDT和TSDTE直接测结构抽取，MedDM/CPGPrompt体现人审后执行，NICE→ASP和MedGuideX把运算约束交给程序，CliCARE强调时序图。[临床分报告及原始出处](clinical_llm_review.md)。

可迁移的分别是结构分解、专家审核、流程动作、可复算程序和时间化事实；不能迁移的假设是“能遍历/能运行/图中有路径就代表判据组满足”。尤其Python中的默认False、缺值补0、条件删除和树的顺序接边，都可能悄悄改变作用域。把程序打包成skill只增加复用与工具入口，本轮未发现这种包装本身提供源文等价保证。

## 5. CNF、DNF与“高阶嵌套”应如何理解

以下是本报告自建的形式说明，不是医学规则：

| 原意结构 | 应保留的表达 | 容易被扁平化成的错误 |
|---|---|---|
| A且(B或C) | `and(A, or(B,C))` | `any(A,B,C)` |
| (A且B)或(C且D) | `or(and(A,B), and(C,D))` | 四项任一或全部 |
| 每位患者至少有一项合格结果 | `∀p:Patient ∃r:ResultOf(p) Q(r)` | `∃r ∀p Q(r,p)` |
| 十二个规定类别中至少三类有证据 | `count_distinct(category, qualified_witness) ≥ 3` | 三个文本行命中同一事实 |
| 评分表中满足范围才累加其分值 | 带区间、互斥档和有符号权重的评分程序 | 把每行都当独立确诊/排除规则 |

前三项可属于一阶逻辑；多层嵌套并不意味着量化了谓词或函数。真实临床散文还含概率、默认、时间、建议和推断权限，不应强行把所有内容压成二值一阶蕴涵。

CNF/DNF可作为编译或审查视图，无须让抽取器直接完成分配展开。保持等价的直接展开可能指数增长；Tseitin等编码引入辅助变量，需要保留定义与投影语义，不能只说输出“等价”。[正规形官方说明](https://www.logicng.org/documentation/formulas/operations/transformations/normal-form-transformations/)、[Avigad §6.1](https://avigad.github.io/lamr/decision_procedures_for_propositional_logic.html)。

还有一个本次跨方法核对得到的迁移约束：**等价证据必须说明采用哪一种逻辑语义。** 在经典二值逻辑中，`A∨¬A`等价于TRUE；若运行时采用Strong Kleene三值而A未知，两式却分别为UNKNOWN和TRUE。开放世界下的经典逻辑蕴涵状态与这种逐算子三值求值，也不是同一语义。因此二值求解器的成功不能直接授权运行程序的三值简化；源公式、编译转换、空值与动作政策必须分别定义。这是形式反例支持的本仓设计推论，不是某篇论文的临床实验结果。[CQL逻辑算子参考](https://cql.hl7.org/09-b-cqlreference.html)

## 6. 实证成绩应怎样读，怎样不能读

| 可核验例子 | 所测能力 | 对本任务的限制 |
|---|---|---|
| FOLIO：语法有效93.9%，执行结论63.8% | 公式生成合法性及问答 | 没有给出整条指南忠实率；历史182/204与正式203题不能混作同一测试集 |
| Logic-LM：自修复执行率79.9→85.8%，已执行准确率80.4→79.9% | 语法/可执行修复和条件准确率 | 语法修复可能降低语义质量 |

| Text2MDT：完整树精确匹配0.490（100例、5次运行均值） | 精确结构抽取 | 不等于医学逻辑所有语义槽位已验证 |

| CPGPrompt：人工校验后的合成病例树执行 | 给定审核结构的路径决策 | 不能估计原始自动提取精度，阳性构成限制特异性解释 |

逐项出处分别见 [FOLIO](https://aclanthology.org/2024.emnlp-main.1229/)、[Logic-LM](https://aclanthology.org/2023.findings-emnlp.248/)、[Synchromesh](https://arxiv.org/pdf/2201.11227)、[Text2MDT](https://arxiv.org/html/2401.02034v1)、[NICE→ASP](https://arxiv.org/pdf/2608.30022)、[CPGPrompt](https://arxiv.org/html/2601.03475v1)。这些不是同模型、同数据、同预算的排行榜。

NL2FOL/FoVer允许背景知识通道，部分研究会修剪冲突理论或回退自然语言答案。FoVer Algorithm 1 会删除冲突辅助定义，后端因此可能验证的是**修改后的理论**；背景补全、修剪及回退都必须记账。它们可能对各自任务有用，却不应默认为“忠实抽取源文”的一部分。[NL2FOL](https://aclanthology.org/2025.findings-ijcnlp.8/)、[FoVer](https://aclanthology.org/2025.tacl-1.61.pdf)。
