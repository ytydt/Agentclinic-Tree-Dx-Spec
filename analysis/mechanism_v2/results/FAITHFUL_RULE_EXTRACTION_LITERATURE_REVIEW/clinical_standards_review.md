# 临床可计算指南与标准：能借用的是明确语义，不能借用零错误承诺

审阅日期：2026-09-06。本分报告补足七组经典语言/官方标准；原始资料和访问限制见 `clinical_standards_sources.json`。没有运行外部语言实现，也没有用临床研究成绩估计本仓的抽取忠实率。

## 1. CQL/ELM：成熟的表达式和数据接口，仍需额外的临床完整性约束

本次核验的是 **CQL 2.0.0，R2 STU1**。ELM 是递归 AST，操作数本身可以是表达式；静态检查沿树计算类型并维护符号作用域。结构化数据、集合、区间、代码及 Retrieve 接口把逻辑与数据供应分开。此处的 semantic validation 指表达式在类型环境中合法，不是核对自然语言原意。[语言语义 §5.1–5.2](https://cql.hl7.org/05-languagesemantics.html)。

一个关键反例是：二元 `and` 有三值真值表，而 `AllTrue` 忽略 null；没有非空成员、甚至源列表为 null 时返回 true。`exists(null)` 则返回 false。`Quantity` 提供单位比较/转换，但实现可有能力差异。不能把这些不同运算一律理解为“缺失传播”。[CQL 运算参考：And、AllTrue、Exists、ConvertQuantity](https://cql.hl7.org/09-b-cqlreference.html)。

**本仓推论：**若十二项诊断标准只编译出两项，或十项未观测后被过滤掉，直接调用列表 AllTrue 可能得到一个合法但不合任务意图的真值。正确迁移需要成员全集、源完整性、患者观测完整性三份记录；未知不能在投影列表时消失。PASP 与 mPAP 量纲相同，因此单位检查还须配合指标身份；CQL 本身不替自由文本桥接者决定这两个名字是否同义。版本化的接口和数据要求值得借鉴，空值算子的具体含义必须逐个审查。

官方提供 CQL→ELM 编译器、JavaScript 执行器及 FHIR 数据供应器。它们编译的是 **CQL 文本**，不是未经审定的指南散文。[参考实现入口](https://cql.hl7.org/10-c-referenceimplementations.html)。因此可以把成熟编译后端作为研究臂，但不能据“用了 HL7 标准”宣称源文翻译已被认证。

## 2. FHIR CPG：先明确意图、再形式化、再接本地数据

**Clinical Practice Guidelines 2.0.0 STU2** 将叙述、半结构、可计算结构、当地可执行实现分为 L1–L4，同时强调它们是连续体。方法明确列出概念词典、准则伪代码、流程和适用范围，再转成 FHIR profiles、CQL、ActivityDefinition 与 PlanDefinition；验证包括正例、负例、边界情景及领域专家审查。[知识层次](https://hl7.org/fhir/uv/cpg/documentation-approach-06-01-levels-of-knowledge-representation.html)、[Methodology：Represent、Translate、Validate、Expert Review](https://hl7.org/fhir/uv/cpg/methodology.html)。

**本仓推论：**“不要用某检查排除疾病”属于推断权限或工作流约束，不能直接塞进疾病关系 `excludes`。一个指南适用人群的排除项，排除的也可能是流程资格而不是疾病。上述层次要求说明条件控制什么动作，正好针对74、773及326的对象错置。它提供知识工程责任分工，不提供任意指南自动转译的成功率。

## 3. PROforma：决策论据与工作流有独立对象，但仍有表示局限

2003年原始语言论文给出流程、表达式和引擎操作的语法/操作语义；本次对该篇只核实原始摘要，详细经验性限制来自已读的2006年原始研究全文。后者采用开发者记录及团队讨论的**定性评价**，指出互斥约束、结构化数据支持及复用论据的局限；同一论据给不同候选使用时需复制，可能因版本更新不一致出错。[2003原始摘要](https://pubmed.ncbi.nlm.nih.gov/12807812/)、[Sutton等，2006：Knowledge acquisition、Notational convenience](https://link.springer.com/article/10.1186/1472-6947-6-20)。

**本仓推论：**候选、论据、获取数据、执行动作应分开，是可借鉴的责任边界；但“有 Argument 对象”并不能自动解决重复证据或错误关联。49的零直接分值行仍改变认领集合、56的父类抢占完整主体，都需要引擎准入和身份策略另行解决。不能将早期语言的定性适用性当作今天 LLM 抽取器的量化保证。

## 4. Asbru：适用资格、时间和计划状态不是一个 relation

1996年意图语言原始摘要将时间化的患者状态与动作意图区分。2002年诊疗结合研究全文则明确使用 filter、suspend、restart、complete、abort 条件；其新生儿黄疸实例把指南适用资格与治疗选择、治疗中止分开，并依据年龄与测量时间作状态抽象。[1996原始摘要](https://pubmed.ncbi.nlm.nih.gov/8947735/)、[Seyfang等，2002，§5–7](https://www.protocure.org/old/Documents/Papers/IJMI02.pdf)。

**本仓推论：**“停止这条路径”不能自动成为“排除这个疾病”；治疗无效、过去事件、当前测量应与其各自时间窗保持绑定。179中当前低氧、历史血小板变化和患者已有心脏病，不能被若干无时间的单原子票替代。该文展示的是人工知识建模实例，不能证明从散文自动抽取了这些时间关系，更不能以计划状态语义直接替代诊断概率模型。

## 5. GLIF3：区分可阅读、可计算和可落地

2000/2004年 GLIF3 原始摘要区分概念流程图、可检查逻辑一致性/完整性的可计算规格，以及可接入当地信息系统的实现规格。此次未成功取得2004全文，只采用摘要明确支持的层次描述，不据二手综述补出算子、unknown 或量词细节。[2000作者机构记录](https://cris.haifa.ac.il/en/publications/glif3-the-evolution-of-a-guideline-representation-format/)、[2004原始摘要](https://pubmed.ncbi.nlm.nih.gov/15196480/)。

**本仓推论：**读得懂的树与可执行的树不是同一验收对象；可执行的树与正确接上当前患者数据也不是同一对象。用这个区分组织产物与评测，比把所有缺陷都叫“LLM 不懂逻辑”更有定位价值。具体后端能力仍以实际选择实现的版本为准。

## 6. OWL 与 SHACL：图可以有组合语义，但图一致性不是病例证据完备

OWL 2 官方 Primer 展示交、并、否定及可嵌套的全称/存在性属性限制；其开放世界语义允许未记录事实仍为真，且不同名字不自动代表不同个体。把知识图谱说成天然只能存孤立三元组并不准确，前提是限制节点、绑定关系及语义没有在存储/查询中丢失。[OWL 2 Primer：Classes、Property Restrictions、Individuals](https://www.w3.org/TR/owl2-primer/)。

SHACL 则检查给定数据图是否符合 shapes；`minCount` 约束值节点数量，规范另有 `and/or/not` 等组合约束。2017规范不定义递归 shapes 的统一验证语义，留给实现处理。此处递归循环不等于有限的嵌套组合。[SHACL：§3.4、§4.2、§4.6](https://www.w3.org/TR/shacl/)。

**本仓推论：**OWL 可以帮助疾病/指标身份及包含关系建模，SHACL 可检查所需字段和结构，但“数据图缺少某节点”不等于患者没有某疾病。一个实际证据节点也不能因多个别名出现就满足三项计数；需说明计数对象是否相异。无论采用哪一种图，源文完整性和诊断动作授权仍是外部责任。

## 7. 三项值得明确写入综合结论的校正

| 容易接受的说法 | 本次审读支持的更准确说法 |
|---|---|
| 成熟标准有 unknown，因此可以直接接管诊断组 | 必须核查每个算子的空值、空集合、量词域及数据完备性含义 |
| 树或图天然是组的一等公民 | 需检查组有没有稳定身份、完整子式、作用域和唯一结论，以及执行器是否只按根表达式触发 |
| 程序/标准验证通过，就解决忠实提取 | 验证只对输入的形式规格负责；源文→规格和患者→事实仍要独立审定 |

这些是对本仓迁移的分析结论，不是宣称经典系统已有与本仓相同的故障，也不构成新方案已改善 MRR 的证据。
