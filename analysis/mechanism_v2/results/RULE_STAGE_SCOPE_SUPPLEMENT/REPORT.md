# Redesign 补充：阶段、适用范围、分支与诊断动作权限

日期：2026-09-08。基于 `cursor4@bbc036e8` 的既有 redesign。**本交付是补充规格与有限可执行验收，不是生产实现，也未证明临床准确率改善。**

## 1. 对本轮两项设计疑问的回答

阶段问题确实需要补强，但不是现行实现完全没有区分。`context_type=treatment` 等已有粗分，部分 gate 也尝试抑制检查/治疗误用；旧 redesign 已提出流程与诊断分离。缺的是可存储、可校验并贯穿每个执行通道的 **阶段、句子意图、结论对象、事件状态与效力许可** 合同。只新增一个 `stage` 枚举，再继续把所有内容变成 disease→finding 行，不足以解决问题。

范围问题也成立，但需要区分表达能力和执行语义。AND/OR/NOT 及有作用域的一阶表达式可以表示明确的有限分支；仅有嵌套 AND 并不能表达所有布尔逻辑。即使表示能力足够，抽取器也未必恢复了源文条件/例外，执行器也未必知道“不适用”不等于“条件不满足”。因此显式 applicability/guard 仍是必要的工程与审核结构；上一版已有此字段，本轮补齐它的分支操作语义与验收。

旧设计覆盖与真实新增要求逐项见 [PRIOR_DESIGN_DELTA.md](PRIOR_DESIGN_DELTA.md)。完整合同见 [SEMANTIC_SUPPLEMENT.md](SEMANTIC_SUPPLEMENT.md)。

## 2. 最小表示增补

| 独立字段 | 负责什么 | 反例 |
|---|---|---|
| `care_process_stages[]` | 诊断、检查、治疗、监测等来源用途，可多值 | 治疗章节内也可能有有效诊断证据，不能整段弃用 |
| `semantic_intent` | 诊断推断、建议行为、资格、证据描述、推断权限 | “必须做 X”不自动成为“X 阳性是 D 的必要条件” |
| 类型化 `target/effect` | 疾病真假或检查/治疗/转诊/流程动作 | 建议检查可完全没有疾病主语 |
| `disease_context[]` | 明确的背景或检查目的，可为空 | 为排查 D 而检查，不证明患者已有 D |
| 事件状态 | 推荐、医嘱、执行、完成、结果及解释 | 完成检查不能当阳性结果 |
| `applicability` 与审核状态 | 人群、场景、时点、方法及任务范围 | 范围 FALSE 是 NOT_APPLICABLE，不是疾病反证 |
| `branch_contract` | 父范围、guard、根规则、覆盖、重叠、else、来源优先级 | 年龄未知不能直接走 else；规则数组先后不决定例外 |
| 来源与许可 | 各关键槽位的跨度、完整性、效力审批 | 合法 JSON 和精确数字都不能自动授权硬诊断 |

阶段标签不是患者事实，章节位置也不是动作权限。推荐力度、诊断必要性和统计关联强度分别表示。多结论源句可拆成共享来源、各有完整目标和动作的多个根规则；不能让组叶子各带诊断 relation，由执行器猜整体效果。

## 3. 工作流结论与疾病结论的边界

“C 时建议做 X”输出 `recommend(X)`；“已开具 X”输出请求事件；“X 已完成但无结果”保留结果未知；只有来源确实规定且患者实际观察到的结果 R，才可以作为关于 D 的证据。治疗资格和禁忌同理：不能由接受治疗倒推适应证，也不能由不适合治疗推断疾病不存在。

“需要活检才能依本指南确立诊断”可能约束诊断确认流程，未做活检只是确认程序未完成；它不自动表示疾病本体不存在。若指南独立陈述某组织结果是疾病必要条件，应另建目标为疾病、条件为组织观察的规则。

反之，治疗反应若确由来源明示具有诊断价值，可以成为跨阶段诊断证据，但需独立的诊断效力、时序和范围依据；不能一律拒绝所有治疗相关来源。补充合同因此同时设置拒绝错误转换与保留合法跨阶段证据的正反样例。

诊断服务只消费合格诊断证据/动作；工作流建议、资格和权限单独记账。不适用、未知、未审核或非诊断行不能先进入 claimants 或 L4，再在最终输出时才被过滤。该约束直接对应 [实现审计](../IMPLEMENTATION_DEFECT_AUDIT/REPORT.md) 的隐藏权重和竞争扣分问题。

## 4. 范围为何不能简单塞进原子条件

设 G 是儿童范围，C 是该范围内的标准，D 是疾病。条件性必要关系是：

\[
(G\land D)\rightarrow C.
\]

它不是 \(D\rightarrow(G\land C)\)。后一写法把儿童身份也变成该病的必要条件，会误排范围外的患者。条件性充分关系则是 \((G\land C)\rightarrow D\)。执行时先判 G，只有 G 明确适用，才依据 C 的根结果和动作许可触发诊断效果。

还有另一种陷阱：计算材料蕴涵 \(G\rightarrow C\)，然后在它为真时确诊 D。G 为假时公式可空真，完全不构成患者疾病证据。本补充用执行状态区分 NOT_APPLICABLE、DEFER_SCOPE、NEEDS_EVIDENCE、NOT_TRIGGERED 及合法动作；这些不是额外的疾病真假值。

分支规则也不能自动补全来源。若只有儿童和老年两套标准，中间年龄段可能属于未覆盖范围。未知年龄不会变成成人；两分支同时适用需处理重叠；例外优先级需有来源或独立审批，不能默认“更具体者胜”。详细分支合同及公式反例见 [SEMANTIC_SUPPLEMENT.md §4–5](SEMANTIC_SUPPLEMENT.md)。

else 还需记录它否定的**具体源条件**，而非对前一根规则的全部适用性取补集。“儿童，否则成人”的儿童规则即使另限院内适用，儿童不在院内也不能因此进入成人分支。本补充使用独立审定的 `else_guard`，保存年龄、场景等条件各自的作用域；该反例已纳入验收。

## 5. 借鉴已有标准，但不继承不匹配的默认语义

本补充借鉴 FHIR 的 Definition/Request/Event 区分、ServiceRequest 与结果资源的分离，以及 PlanDefinition 的适用/启动/停止与动作关系；它们提供信息结构，不能保证源文自动抽取忠实。CQL 的 null 和 if 语义也不能直接替代本合同的未知分支策略。具体主源链接、版本与差异均在 [完整合同](SEMANTIC_SUPPLEMENT.md) 对应段落中。

仓内已有 KG 的人群引用、类型化 FeaturePattern 和 LogicExpression 可复用，但尚未与机械链贯通，也不自动提供本文的诊断效力许可和分支异常处理。[已有设计与内部复用差量](PRIOR_DESIGN_DELTA.md)。

## 6. 迁移与验收

旧扁平行不能机械补 `stage=diagnosis`、`scope=TRUE` 或默认 else。可确定的源/对象结构先转成类型化记录，遗失的人群、例外、检查结果或意图回源重建；不能确定时保留 `legacy_unreviewed` 及原始数据。诊断目标绑定和工作流目标绑定分开，输入事实也须保留请求/执行/结果状态。

建议四个递进对照：原实现；只加字段；字段加通道路由；再加 scope/branch 合同。先固定来源、候选、事实和规则，测阶段/意图、对象、事件状态、范围/例外以及根动作是否正确；再接入自动抽取测端到端。不以丢弃所有复杂规则换取虚假的低错误率，要单列合法跨阶段证据和“无疾病主语”流程规则的召回。
