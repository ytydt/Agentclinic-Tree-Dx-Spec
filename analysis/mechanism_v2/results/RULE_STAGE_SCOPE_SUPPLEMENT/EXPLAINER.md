# 这个目录在讲什么（面向初次阅读者）

共用术语见 [../READER_GUIDE.md](../READER_GUIDE.md)。本文只讲这个目录独有的东西。

## 一句话

指南里有很多句子**不是在下诊断**，而是在建议做检查、说明治疗、限定适用人群。现有流水线把它们一律压成「疾病 → 表现」的行，于是「应该做个 EEG」变成了「EEG 异常是这个病的必要条件」。这个目录给出一份规格，把这些区别显式地写进数据结构里。

## 两个核心区分

### 区分一：这句话在说流程，还是在说疾病

| 原文 | 应该输出什么 | 不能输出什么 |
|---|---|---|
| 「C 情况下建议做 X 检查」 | `recommend(X)`，一个流程动作 | ❌「X 阳性是该病的必要条件」 |
| 「已开具 X」 | 一个请求事件 | ❌ X 的结果 |
| 「X 做完了但没出结果」 | 结果**未知** | ❌ 当成阴性 |
| 「需要活检才能按本指南确诊」 | 确认**程序未完成** | ❌ 该病不存在 |

反过来也要留余地：如果指南**明确说**治疗反应有诊断价值，那它可以作为跨阶段的诊断证据——**不能一刀切地拒绝所有治疗相关的原文**。

### 区分二：适用范围不能塞进条件里

设 G ＝「儿童」，C ＝「该范围内的判据」，D ＝ 疾病。正确的写法是：

\[(G \land D) \rightarrow C\]

**不是** \(D \rightarrow (G \land C)\)。后者会把「是儿童」也变成这个病的必要条件，从而**误排除所有成年患者**。

还有一个更隐蔽的陷阱：直接算蕴涵式 \(G \rightarrow C\) 的真值，然后在它为真时确诊。**G 为假时这个式子空真**，根本不构成任何患者证据。

## 需要解释的专用说法

| 说法 | 平实解释 |
|---|---|
| **stage（阶段）** | 这段原文讲的是诊断、检查、治疗还是随访。可以多值——**治疗章节里也可能有有效的诊断证据，不能整段丢弃**。 |
| **semantic_intent（语义意图）** | 这句话在干什么：做诊断推断、建议行为、说明资格、还是描述证据。 |
| **applicability / guard（适用性 / 守卫）** | 这条规则在什么人群、什么场景、什么时点才适用。 |
| **NOT_APPLICABLE ≠ 反证** | 范围不适用是「这条规则管不着」，**不是**「这个病不存在」。这是本目录反复强调的一条。 |
| **branch_contract（分支合同）** | 一组分支规则（儿童一套、老年一套）必须显式声明：父范围、守卫条件、是否覆盖全部情况、是否重叠、else 分支、优先级来源。 |
| **else_guard** | else 分支必须记录它**具体否定了哪个条件**，而不是对前一条规则的全部适用性取补集。例：「儿童规则」若还限定院内适用，那么一个不在院内的儿童**不能**因此掉进「成人」分支。 |
| **四种执行状态** | `NOT_APPLICABLE`（范围外）、`DEFER_SCOPE`（范围待定）、`NEEDS_EVIDENCE`（缺证据）、`NOT_TRIGGERED`（没触发）。**它们都不是「疾病为假」**。 |
| **acceptance vector（验收向量）** | 一组「给定这个输入，正确输出应该是这个」的样例，用来机器检验实现是否符合规格。 |
| **FHIR 的 Definition / Request / Event** | 医疗信息标准里的三分法：定义（规则本身）、请求（开了医嘱）、事件（实际做了）。本目录借鉴了这个结构，但**没有继承它的默认语义**。 |

## 交付了什么，以及它**不是**什么

**是**：一份规格文档、一批合成样例、一个有限的检查器。最终验收为 **24 个合成根规则、10 个分支集合、116 个作者向量通过，另有 123 项独立检查通过**。

**不是**：
- 不是生产实现——**生产代码一行没改**；
- 全部样例都是 **synthetic（合成的）**，`临床使用授权 = false`；
- 检查器**不做**原文抽取、不做医学术语链接、不做通用 FOL 证明；
- 检查通过**不证明**原文抽取忠实，**不证明**临床有效。

## 一条重要的自我澄清

作者明确说：现有实现**并非完全没有**阶段区分——`context_type=treatment` 这类粗标签已经存在，部分门闸也在尝试抑制检查/治疗的误用。缺的是**可存储、可校验、贯穿每一条执行通道**的完整合同。

所以「只加一个 `stage` 枚举字段，然后继续把所有东西压成疾病→表现的行」是**不够**的。

## 迁移时的红线

旧的扁平行**不能**机械地补上 `stage=diagnosis`、`scope=TRUE` 或默认 else 分支——那是在凭空制造语义。能确定的先转成类型化记录，确定不了的保留 `legacy_unreviewed` 和原始数据。
