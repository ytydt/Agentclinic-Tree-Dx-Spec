# OX：放大候选池（不限 hybrid）+ MCR compat 的最优 K

日期：2026-07-26  
设定：候选池可大于 hybrid；后处理 = MCR R3 方言 compat（dry）→ 截断到最终 K  
扫：后验池 N∈{5…15} × K∈{3…8}；另扫 l1_top2/top3/hybrid  
机器表：[`ox_large_pool_k_sweep.json`](ox_large_pool_k_sweep.json)

## 结论

放开候选后，**最优仍是最终短列表 K=4**；候选池宜用 **后验 Top-7（或 12–15，持平）**，再 MCR→4。

| 配置 | F1 | P | R | vs hybrid_mcr@4 |
|------|-----|------|------|-----------------|
| **后验 N=7 → MCR → K=4** | **0.481** | 0.522 | 0.446 | **+1.15 pp** |
| 后验 N=12/15 → MCR → K=4 | 0.481 | 0.522 | 0.446 | +1.15 pp |
| compat_then_pad @4 | 0.479 | 0.520 | 0.443 | +0.92 pp |
| l1_top3 → MCR → K=4 | 0.479 | 0.520 | 0.443 | +0.92 pp |
| hybrid → MCR → K=4 | 0.470 | 0.510 | 0.435 | — |
| 后验 N=7 → MCR → K=5 | 0.466 | 0.452 | 0.482 | — |

## 要点

1. **更大候选有用，但收益很快饱和**：固定 K=4 时，N=5→7 抬 F1（0.467→0.481）；N>7 基本不再涨。  
2. **最终 K 仍不宜拉大**：同池下 K=4 全面优于 K=5/6/7（F1）；放大 N 不能把最优 K 推到 5+。  
3. **Hybrid 池是瓶颈**：均长 6.2，限制了 MCR 可见集合；换成后验 Top-7+ 可超过 hybrid，并略超 `compat_then_pad@4`。  
4. **Plain Top-K（无 MCR）** 在大 N 下截到 K=4 时 F1 不变（0.465）——增益来自 **MCR 在大池上的 merge/重排**，不是单纯加长列表。

## 建议

- 开放 F1 导向：`pool = 后验 Top-7`（不必更大）+ **MCR compat** + **输出 K=4**。  
- 若必须 K=5：N≈7–10 的 MCR 约 F1=0.466，仍低于 N=7→K=4。  
- 追 Recall 才考虑 K=6–7；F1 会掉到 ~0.45–0.47。
