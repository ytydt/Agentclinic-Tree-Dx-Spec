# 第二轮：骨干与 AB02 落差的根因

Updated: 2026-08-07 · 内部分析，不进入已锁定正文

> **⚠ 第三轮已给出根因，本文件的假设部分（§5 的 H10–H13）就此作废。**
> 落差不是机制差异：流水线臂的 `case_summary` 里逐字含金标准
> （MCQ 选项块；MCR 上 100% 位于选项 A），骨干与基线的输入被显式剥离。
> 输入拉平后 4 次调用的骨干追平 84 次调用的 AB02。
> 见 `INTERNAL_MEMO_mcq_option_leak.md`。
>
> 本文件 §1–§4 的测量本身仍然成立，并且现在有了统一解释：
> 之所以八种选择机制无一可移植，是因为**根本不存在待移植的选择优势**。

本轮执行了 E7–E20 共 25 个臂（DA 100 例 + MCR 切片一 100 例，约 2.3 万次调用），
外加 8 组零调用重算。所有选择阶段的臂都是**配对设计**：S1–S3 复用同一批
`case_stages`，只有 S4 变化，因此不受下面第 1 节的噪声地板影响。

---

## 0. 一句话结论

**落差不在选择端，而且选择端根本不存在可移植的机制。**

八种不同实现的证据裁决（稀疏单胜者 / 稀疏 top-3 带秩权重 / 稠密序数 + 判别门控 /
单次全矩阵；双向分离 vs 合并；4→32 次调用；复合事实 vs 原子化事实）**在两个数据集上
无一例外地低于"0 次调用、直接取 S3 首项"**。与此同时，零调用重算显示 AB02 自己的
level-2 后验在 **97/100 的病例里只经历了恰好一次序数更新**——占其 71% 预算的
约 60 次证据裁决调用，在 flat 臂里作用于被压平成单节点的 L1 轴，对最终排序
没有任何影响，是死算力。

唯一可移植、且在两个数据集上都复现的机制是**入口广度**：多次异条件 DDx 调用取并集，
+1 次调用即 DA option@1 0.50→0.58、MCR 0.24→0.28。

## 1. 先修三个测量缺陷（其中两个会推翻既有判定）

### 1.1 温度 0 不可复现，n=100 上的噪声地板是 ±0.05

`e7_k3_comp` 与 `e8_k3_part` 的**第一次 S2 调用载荷完全相同**（同提示、同锚点、
同模型、temperature=0），可作天然重测。结果：

| | run 1 | run 2 | 配对不一致 |
|---|---:|---:|---|
| S1 syndrome_frame 逐字相同 | — | — | 27/100 不同 |
| S2 首次调用列表逐项相同 | — | — | 96/100 不同 |
| S2 首项正确率 | 0.36 | 0.41 | b/c = 1/6（翻转 7%） |
| S2 列表覆盖率 | 0.72 | 0.74 | 3/5（翻转 8%） |

配对差标准误 ≈ 0.026 → **同配置重跑 95% 波动带 ±0.05，臂间差异小于约 0.10 不可解释。**

**影响**：`RESULTS.md` 里 E4（k=5 vs k=8，Δ0.02）、E5（S4-b vs S4-c，Δ0.05）
两条判定都在噪声内，应从"结论"降级为"未测出差异"。骨干 vs AB02 的 0.28 差距、
E10 的 0.16 差距不受影响。

### 1.2 AB02"入口首项 0.50"是循环统计，实际两边持平

`z2_da_funnel` 报的 AB02 DDx 首项 0.50 有两层污染。第一层已知（`lists[0]` 是哈希序）；
本轮发现第二层更严重：

- 6 次 DDx 调用的首项**有 78% 落在最终 5 叶集内**（随机基线 5/19 ≈ 0.26）
- 6 次首项的去重率仅 0.34（≈ 只有 2 个不同值）

即后续 DDx 调用是**被当前候选集条件化**的，"入口首项正确率"是在自己的选择结果
喂回入口之后测的。新鲜单次调用的真实值：AB02 探针 0.36、骨干 0.37。
**入口排序上两者没有差距**，此前记录的 13pp 缺口不存在。

### 1.3 E3（KB-only 消融）的作废与 E10 的正确判定

E3 因 S3 不校验 `shortlist ⊆ S2` 而无效（20% 越池）。E10 把 S3 改成返回池内下标
（越池 0/500，非法下标 0）后重做：

| 臂 | covS2 | covS3 | lexical | option@1 |
|---|---:|---:|---:|---:|
| e3_kb_only（泄漏版） | 0.44 | 0.58 | 0.44 | 0.57 |
| e10_kb_strict | 0.43 | 0.40 | 0.28 | **0.43** |
| e10_llm_strict | 0.72 | 0.61 | 0.38 | **0.59** |

同一严格 S3 下 **LLM 入口 0.59 vs KB 入口 0.43，Δ=0.16 > 噪声地板 0.10 →
LLM-DDx 入口确认为承重机制。** E3 原来"不确认"的判定完全由泄漏造成。

附带：严格下标式 S3 不劣于自由文本 S3（0.38/0.59 vs 0.36/0.50），且可校验、
不会发明池外实体，应作为默认实现。

## 2. 唯一可移植的机制：入口广度（E7 / E8）

S2 改为 k 次异条件调用取并集。两种条件化方式：
`complement`（把已有列表喂回去，要求补充遗漏）与
`partition`（把病因空间固定切成 3 个互斥类，每次只在一个类内穷举）。

| 臂 | 调用 | 池大小 | covS2 | covS3 | lexical | option@1 |
|---|---:|---:|---:|---:|---:|---:|
| k=1 基线 | 4 | 17.3 | 0.71 | 0.59 | 0.36 | 0.50 |
| k=2 complement | 5 | 31.4 | 0.79 | 0.63 | 0.41 | **0.58** |
| k=3 complement | 6 | 47.6 | 0.79 | 0.62 | 0.40 | **0.59** |
| k=3 partition | 6 | 36.9 | **0.81** | **0.65** | **0.43** | 0.57 |
| AB02（6 次 DDx） | 84 | 19.2 | 0.92 | 0.80 | 0.64 | 0.68 |

结论：
1. **+1 次调用买到 +0.08 option@1，k=2 即饱和。** MCR 独立复现（0.24 → 0.28）。
2. **H1b 成立**：等预算下 partition 的池小 23%、覆盖更高、最终更高——
   "层级"的真实价值是**召回的条件化划分器**，不是分类学本身。
3. **增益一半被 S3 吃掉**：covS2 +8pp 只换来 covS3 +4pp，B 桶从 12 涨到 17。
   池越大，单次 S3 过滤丢得越多。这是下一步该投工程的地方，不是 S4。
4. 跨次共识排序（RRF / 投票）**无效**（0.35 vs 0.36）——complement 设计使各次
   列表天然不重叠，投票无信息。若要用共识排序必须配同分布重采样。

## 3. 选择阶段：八种实现全部为负（E9 / E12 / E18 / E19 / E20）

全部配对复用 `v0_s4b_k5` 的 S1–S3（shortlist 集合 100/100 一致），只有 S4 变化。

| S4 变体 | 调用 | lexical | option@1 |
|---|---:|---:|---:|
| **S4-a 直接取 S3 首项（不调用）** | **0** | **0.36** | **0.50** |
| S4-b 自由选择（一次 gestalt） | 1 | 0.36 | 0.50 |
| S4-d 逐事实全矩阵（一次，全局可见） | 1 | 0.31 | 0.55 |
| S4-f 单事实近视 · 双向合并 m=4 | 4 | 0.23 | 0.43 |
| S4-e 单事实 · 双向分离 m=4 | 8 | 0.22 | 0.45 |
| S4-e 单事实 · 双向分离 m=8 | 16 | 0.23 | 0.48 |
| S4-e 单事实 · 双向分离 m=16 | 32 | 0.28 | 0.42 |
| S4-e 双向分离 m=8 · 中性事实源 | 16 | 0.31 | 0.52 |
| S4-g 稀疏 top-3 + 秩权重(1/.5/.25) m=12 | 12 | 0.32 | 0.45 |
| S4-g top-3 + **原子化事实** m=16 | 17 | 0.22 | 0.40 |
| S4-h **稠密序数 + §13 判别门控** m=10 | 10 | 0.24 | 0.36 |
| S4-h 稠密序数 + 门控 + 原子化 m=16 | 17 | 0.20 | 0.40 |

MCR 切片一 Prompt-7 Acc@1 独立复现同一方向：
基线 0.24 → S4-d 0.19 → S4-h 0.14 → S4-e(m=8) 0.11 → S4-g 原子化 0.09。

### 逐条被证伪的假设

- **H2「选择增益需要与生成先验去相关的信号」** → 证伪。把 rule-in / rule-out
  拆成模型互不可见的两次调用（最强的去相关手段）比合并成一次**更差**
  （0.22 vs 0.23），两者都远低于不调用。
- **H「是票密度不够」** → 证伪。剂量响应 m=4→8→16（8→16→32 次调用）
  lexical 0.22→0.23→0.28，单调上升但 32 次调用仍到不了 0 次调用的 0.36。
- **H9「事实必须原子化」** → 证伪，且反向。AB02 喂的是每例 17.55 条
  `类型: 值` 的单属性原子（`Lesion location: lower legs`），我复制了这个格式：
  投票数 27→29、中位边际 1.92→2.20、平局 6→4——**聚合更果断了，准确率反而
  从 0.32 掉到 0.22**。不是信噪比问题，是逐事实判别本身在此设置下反信息。
  机理：原子化把一处复合体征拆成 4 条，该体征就投 4 票，与其诊断价值无关。
- **H「缺的是 §13 判别门控」** → 证伪。照抄 `updater.ordinal_update` 的稠密
  七级序数标签 + 门控（冻结率 37%，符合设计预期），得分 0.24/0.36，是所有臂里
  最低的一档。
- **H「AB02 用了更强的模型」** → 排除。`stage_manifest` / 缓存里唯一的模型是
  `meta-llama/llama-3.3-70b-instruct`，与骨干一致。
- **H「AB02 的证据机看到了答案选项」** → 排除。`l2_option_l3_annotation.py`
  （在 `(L2 叶 × 选项)` 对上打分并直接输出选项排名）只被
  `scripts/eval_l2_option_l3_annotation.py` 调用，**不在 c3_ab02 的 annotate 路径里**。

### 反向的正面结论

- **S3 是排序器，S4 是破坏者。** S2 首项 0.36 → S3 首项 0.44（+8pp）→
  S4-b champion 0.40（−4pp）。**E16 删掉 S4 直接取 S3 首项：lexical 0.44。**
- 唯一在 option@1 上高于基线的是 S4-d（0.55 vs 0.50），但它的 lexical 反而更低
  （0.31 vs 0.36）。原因是 S4-d 会按证据分**重排整个 shortlist**，而 option@1
  读的是整张排序表——即"证据打分对整表排序有用、对 argmax 有害"。

## 4. AB02 那 84 次调用到底在干什么（零调用重算）

跨全部三个缓存的模块清单（101 例均值）：

| 模块 | 次/例 | 归类 |
|---|---:|---|
| `favored` + `why`（bfs） | 13.02 | L1 证据裁决 |
| `argues_against` + `why`（bfs） | 13.01 | L1 证据裁决 |
| `ranked_facts` + `verdict`（bfs） | 12.59 | 事实选择器 |
| `needs_expansion` / `knowledge_query`（l2） | 9.86 | 叶集构造 |
| `ranked_facts` + `verdict`（l2） | 9.01 | 事实选择器 |
| `ranked_facts` + `verdict` + `why`（l2） | 6.63 | 事实选择器 |
| `per_fact_effects` + `fact_rationales`（l2） | 5.67 | 证据矩阵 |
| `assignments`（l2） | 5.57 | 候选绑定 |
| **`differentials`（l2）** | **5.57** | **召回入口** |
| `ranked_candidate_ids` + `why`（l2） | 1.99 | 联合仲裁 |
| granularity support/contradict | 0.99 | 粒度校准 |
| **合计** | **83.98** | |

**召回入口只占 6.6%，证据裁决占 71%。**

关键的三个零调用事实：

1. **最终答案 = 后验 argmax，100/100 一致。** 那 1.99 次联合仲裁调用一次都没有
   推翻算术结果。决定诊断的是确定性累加，不是任何一次 LLM 的整体判断。
2. **叶集生成序首项 0.55 → 后验 argmax 0.64**，即整个证据栈净贡献 +0.09。
3. **但 97/100 的病例里，level-2 分支存的 `prior` 仍是精确的 1/k 均匀值。**
   由于 `update_leaf_posteriors` 每次更新都执行 `branch.prior = branch.posterior`，
   这意味着**叶集后验只经历了恰好一次序数更新**。最大后验/均匀先验的倍率中位
   2.57，与单次 `strong_for`(3.0) / `moderate_for`(1.8) 归一化后完全吻合。

第 3 点是本轮最重要的发现：**bfs 缓存里那 38.6 次/例的 `favored`/`argues_against`/
事实选择调用作用于 L1 轴，而 AB02 的 L1 轴被压平成了单节点，因此它们在数学上
不可能移动 level-2 叶排序。约 60 次证据裁决调用（71% 预算）在这个臂里是死算力。**

顺带排除的两条：
- 事实选择器不是过滤器：verdict 分布 select 2802 / none 37 / abstain 13，
  弃权率仅 2%，且 17.55 条可用事实里用掉 14.2 条（81%）。
- 叶集生成不是第二召回入口：17% 的叶标签不在 DDx 池中，但**金标准仅经叶生成
  才出现的病例为 0**。它是重命名器（词数 2.62 → 2.82），不增加召回。
- 粒度错配不是差异来源：骨干 9–10%、AB02 8%，两边同一水平。

## 6. 第三轮假设

### H10 —— 承重的是"候选集构造"，不是入口也不是选择（最高优先级）
AB02 在 DDx 池 → 5 叶集这一步花约 15 次调用（`needs_expansion` 9.86 +
`assignments` 5.57），把 0.92 覆盖压到 0.80（留存 87%）且首项升到 0.55；
我花 1 次 S3，把 0.81 压到 0.65（留存 80%）、首项 0.44。
**E21**：把 S3 拆成「逐候选保留/剔除判定（批 5 个一次调用，k/5 次）+ 确定性合并」，
预算 3–4 次。判据：covS3 ≥ 0.72 且首项 ≥ 0.50。

### H11 —— 证据打分只对整表排序有用，对 argmax 有害
S4-d 是唯一 option@1 高于基线的臂（0.55 vs 0.50）而 lexical 更低。
**E22**：保留 S3 首项作为 champion，仅用证据分重排 shortlist 的 2..k 位，
量 option@1 与 top-3。若成立，证据机的正确用法是**尾部排序**而非选主。

### H12 —— AB02 的 +0.09 不可移植，因为它耦合在自己的状态上
单次稠密序数更新，在 AB02 上把 0.55 抬到 0.64，在我的 shortlist 上把 0.36 压到 0.24。
差别在于 AB02 的叶携带 `why_included` 证据出处、且由同一生成回路产出，
其"后验"很可能只是在重新表达叶集构造阶段已有的信息。
**E23**：让 S3 每个候选连同 `why_included` 一起返回，把这些出处喂进 S4-h。
若此时才转正，则机制是"带证据出处的候选"，而非任何打分规则。
**在 E23 出结果前，正文不应把证据/后验更新写成独立的承重机制。**

### H13 —— 池增长后 S3 是新瓶颈
covS2 +8pp 只换来 covS3 +4pp。**E24**：S3 的 max_k 随池大小放开到 8–10，
或改成两级（先粗筛 15，再精筛 5），量 covS3 与首项。

## 7. 对正文的风险提示

1. **"证据驱动的层级推理"作为承重机制的说法有严重风险。** 在 flat 臂里，
   占 71% 预算的证据裁决作用于被压平的 L1 轴，数学上不影响最终排序；
   而 flat 臂（0.64/0.68）与完整模型在 DA 上仅差 0.02、在 MCR 上差 0.025
   （p=0.405，方向在两切片间翻转）。**层级轴与其证据栈合起来的净贡献接近零。**
2. **E4 / E5 的判定应降级**为"未测出差异"（噪声地板 ±0.05）。
3. **入口广度是唯一在两个数据集上都站得住的机制**，且 +1 次调用即饱和，
   这是一个正面且诚实的可写结论。
4. **粒度校准（0.99 次/例）**在两边的错配率相同（8% vs 9–10%），
   不构成差异来源。
